# Interfaces: /huf vs /app

Huf exposes two distinct frontend interfaces served from different URL paths. Understanding the difference helps you choose the right one for your deployment.

---

## /huf — The Huf App Interface

**URL:** `{your-frappe-site}/huf`

This is the main Huf application UI, built as a React single-page application. It is the primary interface for both end-users and administrators to interact with the Huf system.

### Who uses it?
- **Huf Admins** — configure agents, providers, models, tools, flows, and knowledge sources.
- **Huf Managers** — create and manage agents, flows, and knowledge.
- **Huf Users** — chat with agents, view conversations, run flows.
- **Huf Viewers** — read-only access to conversations.

### What's in /huf?

| Section | What you can do |
|---|---|
| **Agents** | Create, configure, and manage agents. View agent runs and conversation history. |
| **Chat** | Open a chat session with any agent that has `allow_chat` enabled. Real-time streaming responses with markdown rendering. |
| **Flows** | Build and manage visual AI workflows using the drag-and-drop flow builder. |
| **Knowledge** | Manage knowledge sources, view indexing status, and add documents. |
| **Tools** | Browse and configure Agent Tool Functions and MCP Servers. |
| **Settings** | Configure AI Providers, AI Models, and provider-specific settings (ElevenLabs, OpenAI TTS, Groq). |
| **Roles & Users** | Manage Huf Roles and assign them to users (Admin/Manager only). |

### Access Control

The `/huf` interface checks the user's **Huf Role** on load. If a user has no Huf Role and is not a System Manager, they are redirected away. Module visibility within the app is further controlled by capabilities assigned to the user's role.

The current user's role and capabilities are fetched on load via:

```
GET /api/method/huf.permissions.get_me
```

This returns:
```json
{
  "user": "jane@example.com",
  "full_name": "Jane Doe",
  "huf_role": "Huf Manager",
  "capabilities": ["agent.use", "agent.create", "chat.use", ...]
}
```

## /app — The Frappe Desk Interface

**URL:** `{your-frappe-site}/app`

This is the standard Frappe Desk interface. Huf DocTypes are accessible here for administrators who prefer working in the traditional Frappe form view.

### When to use /app for Huf?

- **Advanced configuration** — editing DocType schemas, permission rules, or system settings not exposed in the Huf UI.
- **Report access** — using Frappe's built-in List View and Report builder for Agent Runs, Agent Messages, etc.
- **Debugging** — inspecting raw document records for Flow Runs, Agent Conversations, and Agent Runs.
- **Frappe integrations** — connecting Huf DocTypes to Frappe Workflows, Notifications, or Custom Fields.

### Huf DocTypes in /app

All Huf DocTypes appear in the Frappe Desk module list under **Huf**:

```
/app/agent            → Agent list + form
/app/agent-run        → Agent Run log
/app/agent-message    → Agent Message log
/app/agent-trigger    → Trigger configuration
/app/flow-definition  → Flow definitions (raw JSON editing)
/app/flow-run         → Flow Run log
/app/knowledge-source → Knowledge Source management
/app/mcp-server       → MCP Server configuration
/app/agent-console    → Quick-test console (singleton)
```

## Choosing the Right Interface

| Task | Use |
|---|---|
| Chat with an agent | `/huf` Chat |
| Build a flow | `/huf` Flows |
| Configure a new provider | `/huf` Settings |
| View raw Agent Run JSON | `/app/agent-run` |
| Grant a user access to Huf | `/huf` Roles → Assign Role, or `/app/huf-user-role` |
| Set up a Doc Event trigger | `/huf` Agents → Triggers tab, or `/app/agent-trigger` |
| Inspect flow execution state | `/app/flow-run` |
| Add knowledge documents | `/huf` Knowledge |

## Real-Time Features

Both interfaces rely on **Frappe Realtime** (Socket.IO) for live updates:

- **Chat** — agent responses are streamed token-by-token to the browser without polling.
- **Flow Builder** — flow run status updates (node activation, completion) are pushed in real-time.
- **Tool Execution Status** — tool call events are pushed as the agent works.

Realtime requires the Frappe socket server (`frappe-socketio`) to be running. In production, this is typically started with `bench start` or a dedicated Supervisor process.

## Guest Access

Some Huf functionality can be exposed to unauthenticated (Guest) users:

- **Agent API** — individual agents can set `allow_guest = true`. Guest users can then call `run_agent_sync` without logging in.
- **HTTP Tool Handler** — tools with `allowed_for_guest = true` can be called by unauthenticated requests.

> [!CAUTION]
> Enable guest access only for agents that are explicitly designed for public use. Always validate inputs and limit tool capabilities on guest-accessible agents to prevent misuse.
