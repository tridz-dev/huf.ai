# Publishing Tools (App Provided)

HUF's **App Seeding** system lets any Frappe app bundle pre-built agents, tools, prompts, knowledge sources, and triggers as JSON definition files. When the app is installed, HUF automatically seeds these definitions into the Frappe database — ready to use without any manual configuration.

This page documents how to package and publish HUF tools and agents as part of a Frappe app.

---

## Overview

App Seeding works by scanning installed Frappe apps for a `huf/` directory within the app's Python package. If found, HUF reads JSON files from predefined sub-folders and upserts them as Frappe documents.

The seed folders and their corresponding DocTypes are:

| Folder | DocType Seeded |
|---|---|
| `huf/prompts/` | `Agent Prompt` |
| `huf/tools/` | `Agent Tool Function` |
| `huf/knowledge/` | `Knowledge Source` |
| `huf/agents/` | `Agent` |
| `huf/triggers/` | `Agent Trigger` |

Load order is fixed: **prompts → tools → knowledge → agents → triggers**. This ensures dependencies are available before the documents that reference them.

---

## Directory Structure

```
my_frappe_app/
├── my_frappe_app/          # Python package root
│   ├── huf/                # HUF seed directory (scanned automatically)
│   │   ├── tools/
│   │   │   ├── my_tool.json
│   │   │   └── another_tool.json
│   │   ├── agents/
│   │   │   └── my_agent.json
│   │   ├── prompts/
│   │   │   └── my_prompt.json
│   │   ├── knowledge/
│   │   │   └── my_knowledge.json
│   │   └── triggers/
│   │       └── my_trigger.json
│   ├── __init__.py
│   └── ...
```

<Callout type="info">
  HUF also checks for a `huf/` directory at the app root (e.g., `apps/my_frappe_app/huf/`) as a fallback. The Python package path is checked first.
</Callout>

## Seeding Tools

Each `.json` file in `huf/tools/` defines one or more `Agent Tool Function` documents.

### Tool JSON Schema

```json
{
  "tool_name": "search_products",
  "description": "Search the product catalog by name or SKU.",
  "types": "Custom Function",
  "function_path": "my_app.tools.search_products",
  "tool_type": "Catalog Tools",
  "parameters": [
    {
      "fieldname": "query",
      "type": "string",
      "required": 1,
      "description": "Search query (product name or SKU)"
    },
    {
      "fieldname": "limit",
      "type": "integer",
      "required": 0,
      "description": "Maximum number of results (default 10)"
    }
  ]
}
```

A JSON file can contain either a single object or a JSON array of objects — both are supported.

### Valid `types` Values for Seeded Tools

| Type | Description |
|---|---|
| `Custom Function` | Calls a Python function via `function_path` |
| `App Provided` | Same as Custom Function but marks the tool as owned by the app |
| `Get Document` | Read a Frappe document |
| `Get List` | Query a Frappe DocType list |
| `Create Document` | Create a Frappe document |
| `Update Document` | Update a Frappe document |
| `Delete Document` | Delete a Frappe document |
| `Submit Document` / `Cancel Document` | Workflow transitions |
| `Get Value` / `Set Value` | Single field read/write |
| `Get Report Result` | Run a Frappe report |
| `GET` / `POST` | HTTP tool |
| `Run Agent` | Chain to another agent |
| `Client Side Tool` | Frontend-executed tool |

If `types` is not a valid value, the loader automatically sets it to `App Provided`.

### Tool Type Auto-Creation

If the `tool_type` value in your JSON does not yet exist as an `Agent Tool Type` document, HUF creates it automatically during seeding.

### Provenance Fields

Every seeded document gets two hidden fields set automatically:

| Field | Value |
|---|---|
| `source_app` | The Frappe app name that seeded this document |
| `source_file` | Relative path within the app (e.g., `huf/tools/my_tool.json`) |

These are stored on the `Agent Tool Function` document and can be used to track which app owns each tool.

## Seeding Agents

Each `.json` file in `huf/agents/` defines an `Agent` document.

### Agent JSON Schema

```json
{
  "agent_name": "Product Assistant",
  "instructions": "You are a helpful product assistant. Use the available tools to answer questions about our product catalog.",
  "provider": "OpenAI",
  "model": "gpt-4o",
  "temperature": 0.3,
  "allow_chat": 1,
  "tools": [
    "search_products",
    "get_product_details"
  ],
  "knowledge": [
    "Product Documentation"
  ]
}
```

The `tools` array is a list of `Agent Tool Function` names (tool_name values). The loader converts them to the `agent_tool` child table format. Similarly, `knowledge` is converted to the `agent_knowledge` child table.

## Seeding Prompts

Each `.json` file in `huf/prompts/` defines an `Agent Prompt` document.

### Prompt JSON Schema

```json
{
  "title": "Product Assistant System Prompt",
  "content": "You are a helpful product assistant for Acme Corp...",
  "category": "Sales"
}
```

## Seeding Knowledge Sources

Each `.json` file in `huf/knowledge/` defines a `Knowledge Source` document.

### Knowledge Source JSON Schema

```json
{
  "source_name": "Product Documentation",
  "description": "Official product documentation and FAQs",
  "storage_mode": "Frappe File",
  "knowledge_type": "sqlite_fts"
}
```

## Seeding Triggers

Each `.json` file in `huf/triggers/` defines an `Agent Trigger` document.

### Trigger JSON Schema

```json
{
  "trigger_name": "New Lead Notifier",
  "agent": "Product Assistant",
  "trigger_type": "Doc Event",
  "reference_doctype": "Lead",
  "doc_event": "after_insert",
  "condition": "doc.lead_name != ''"
}
```

## When Seeding Runs

### On App Install

HUF hooks into Frappe's `after_app_install` event via `on_app_installed()` in `seeder.py`. When any app is installed on the bench, HUF automatically checks if it has a `huf/` seed directory and runs seeding immediately.

### Manual Trigger

System Managers can re-run seeding at any time:

**From the UI:** Go to **HUF Workspace → Seed All Apps** (calls `seed_all_apps()` whitelisted endpoint).

**From the bench:**
```bash
bench execute huf.ai.app_seeding.seeder.seed_all
```

**For a specific app:**
```bash
bench execute huf.ai.app_seeding.seeder.seed_app --kwargs '{"app_name": "my_app"}'
```

### Upsert Behavior

Seeding is **idempotent** — running it multiple times is safe. The upsert logic:

- If a document with the same key field (e.g., `tool_name`) already exists: **update it** with the JSON data
- If it doesn't exist: **create it**

This means you can update your seed files and re-run seeding to push changes to installed instances.

## App Provided vs Custom Function

Both `App Provided` and `Custom Function` tool types call a Python function via `function_path`. The difference is semantic and organizational:

| | `Custom Function` | `App Provided` |
|---|---|---|
| Intended for | One-off custom tools created in HUF UI | Tools shipped by a Frappe app as part of its feature set |
| `provider_app` field | Not used | Set to the app name |
| Seeded via | Manual UI creation | App Seeding (JSON files in `huf/tools/`) |
| Provenance tracking | None | `source_app` and `source_file` fields |

When seeding sets `types = "App Provided"`, it also sets `provider_app` to the seeding app's name via the `source_app` provenance field.

## Example: Publishing a Complete App

Here is a full example of an app that ships an "HR Assistant" agent with a custom tool:

**`hr_assistant/huf/tools/get_employee_info.json`**
```json
{
  "tool_name": "get_employee_info",
  "description": "Get information about an employee including their department, designation, and manager.",
  "types": "App Provided",
  "function_path": "hr_assistant.tools.get_employee_info",
  "tool_type": "HR Tools",
  "parameters": [
    {
      "fieldname": "employee_id",
      "type": "string",
      "required": 1,
      "description": "The employee ID (e.g., EMP-00001)"
    }
  ]
}
```

**`hr_assistant/tools.py`**
```python
import frappe

def get_employee_info(employee_id: str, **kwargs) -> dict:
    """Retrieve employee information."""
    if not frappe.has_permission("Employee", "read", employee_id):
        return {"error": "Access denied"}
    
    employee = frappe.get_doc("Employee", employee_id)
    return {
        "name": employee.employee_name,
        "department": employee.department,
        "designation": employee.designation,
        "manager": employee.reports_to
    }
```

**`hr_assistant/huf/agents/hr_assistant.json`**
```json
{
  "agent_name": "HR Assistant",
  "instructions": "You are an HR assistant. Help employees find information about policies, colleagues, and HR processes.",
  "provider": "OpenAI",
  "model": "gpt-4o-mini",
  "allow_chat": 1,
  "tools": ["get_employee_info"]
}
```

When the `hr_assistant` app is installed, HUF seeds `get_employee_info` as an `Agent Tool Function` and `HR Assistant` as an `Agent`, fully linked and ready to use.

## Seed Result Reporting

`seed_app()` returns a `SeedResult` dataclass:

```python
@dataclass
class SeedResult:
    app: str       # App name
    seeded: int    # Documents successfully created/updated
    skipped: int   # Documents that failed or were skipped
    errors: list   # List of error messages for failed items
```

Errors during seeding are also logged to **Frappe Error Log** under the `"App Seeding Error"` title. Review these logs if tools or agents are missing after installation.
