# Built-in Integration Tools

HUF ships with a set of ready-made integration tools covering the most common third-party services. These tools are defined in `huf/ai/tools/_registry.py` and are seeded into your Frappe instance on setup (or on demand via App Seeding).

<Callout type="info">
  All built-in tools are grouped under categories — **Communication Tools** and **Google Tools** — and appear as `Agent Tool Function` documents that you can assign to any agent.
</Callout>

## Credential Management

Built-in tools retrieve their credentials from **Integration Settings**, not environment variables directly. Credentials are stored per-service in the `Integration Credential` child table (key/value pairs, values encrypted via Frappe's Password field type).

To configure credentials:

1. Go to **HUF → Integration Settings**
2. Find the service row (e.g., `slack`, `gmail`, `github`)
3. Expand the **Credentials** child table
4. Add the required key/value pairs

The `get_credential(service_name, key)` helper in `huf/ai/tools/credentials.py` reads from this table at runtime. If a credential is missing, the tool returns an error message rather than throwing an exception.

There is also a `get_integration_recipient` tool (see [Recipient Lookup](#recipient-lookup)) that lets agents resolve a human-friendly recipient name to the service-specific ID using **Integration Recipient** documents.

## Recipient Lookup

The `get_integration_recipient` tool is a cross-service helper that should be called **before** sending messages to named contacts.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `service` | string | ✅ | Service name: `telegram`, `slack`, `discord` |
| `recipient_name` | string | ✅ | Human-friendly name stored in Integration Settings |

**How to use:** Call this first to get a `recipient_id`, then pass that ID to the service's send tool (e.g., `telegram_send_message`).

## Slack

**Category:** Communication Tools  
**Required credential key:** `token` (Bot Token with appropriate scopes)

Store in Integration Settings under service name `slack`, key `token`.

### Tools

#### `slack_send_message`

Send a message to a Slack channel.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `channel` | string | ✅ | Channel ID or name (e.g., `#general` or `C012AB3CD`) |
| `text` | string | ✅ | Message text (supports Slack mrkdwn formatting) |

#### `slack_send_thread_reply`

Reply to an existing message thread in a Slack channel.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `channel` | string | ✅ | Channel ID or name |
| `text` | string | ✅ | Reply text |
| `thread_ts` | string | ✅ | Timestamp of the parent message (`ts` field) |

#### `slack_list_channels`

List all channels (public and private) in the workspace.

_No parameters required._

#### `slack_get_channel_history`

Get message history from a Slack channel.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `channel` | string | ✅ | Channel ID to fetch history from |
| `limit` | integer | ❌ | Max messages to fetch (default: 100, hard cap: 200) |

#### `slack_search_messages`

Search messages across the workspace. Supports Slack modifiers like `from:@user`, `in:#channel`.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `query` | string | ✅ | Search query string |
| `limit` | integer | ❌ | Max results (default: 20, max: 100) |

#### `slack_list_users`

List all active users in the workspace.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `limit` | integer | ❌ | Max users to fetch (default: 100, hard cap: 200) |

### Setup

```
Integration Settings → slack → Credentials
  key: token     value: xoxb-your-bot-token
```

Your Slack bot must have scopes: `channels:read`, `channels:history`, `chat:write`, `search:read`, `users:read`.

## Gmail

**Category:** Google Tools  
**Required credentials:** OAuth2 — `client_id`, `client_secret`, `refresh_token`

Store in Integration Settings under service name `gmail`.

Gmail tools use OAuth2 refresh token flow. An access token is obtained automatically by calling Google's token endpoint each time.

### Tools

#### `gmail_get_emails`

Retrieve the latest emails from Gmail inbox.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `count` | integer | ❌ | Number of emails to retrieve (default: 10) |
| `query` | string | ❌ | Gmail search query (e.g., `is:unread from:boss@company.com`) |

Returns: `id`, `threadId`, `subject`, `from`, `date`, `snippet` per message.

#### `gmail_send_email`

Send an email via Gmail.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `to` | string | ✅ | Recipient email address |
| `subject` | string | ✅ | Email subject |
| `body` | string | ✅ | Email body (plain text) |

#### `gmail_create_draft`

Create a draft email in Gmail (does not send).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `to` | string | ✅ | Recipient email address |
| `subject` | string | ✅ | Email subject |
| `body` | string | ✅ | Email body |

#### `gmail_mark_as_read`

Mark an email as read (removes `UNREAD` label).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `message_id` | string | ✅ | Gmail message ID |

### Setup

```
Integration Settings → gmail → Credentials
  key: client_id       value: <your-google-client-id>
  key: client_secret   value: <your-google-client-secret>
  key: refresh_token   value: <your-refresh-token>
```

To obtain a refresh token, complete a Google OAuth2 consent flow with the `gmail.modify` scope.

## GitHub

**Category:** Developer Tools  
**Required credential:** `access_token` (GitHub Personal Access Token or OAuth token)

Store in Integration Settings under service name `github`, key `access_token`.

### Tools

#### `github_list_repos`

List repositories for the authenticated user (sorted by last updated, up to 30).

_No parameters required._

#### `github_get_repo`

Get details of a specific GitHub repository.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `repo_name` | string | ✅ | Repository in `owner/name` format (e.g., `octocat/Hello-World`) |

Returns: name, description, URL, stars, forks, open issues, language, default branch.

#### `github_create_issue`

Create a new issue in a GitHub repository.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `repo_name` | string | ✅ | Repository in `owner/name` format |
| `title` | string | ✅ | Issue title |
| `body` | string | ❌ | Issue body (markdown supported) |

#### `github_create_pr`

Create a pull request in a GitHub repository.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `repo_name` | string | ✅ | Repository in `owner/name` format |
| `title` | string | ✅ | PR title |
| `body` | string | ❌ | PR description (markdown supported) |
| `head` | string | ✅ | Head branch (the branch with changes) |
| `base` | string | ✅ | Base branch (target branch, e.g., `main`) |

#### `github_get_file`

Get the content of a file from a repository.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `repo_name` | string | ✅ | Repository in `owner/name` format |
| `path` | string | ✅ | File path within the repository (e.g., `src/index.js`) |

Returns: file name, path, SHA, size, URL, and decoded content.

#### `github_search_code`

Search code across GitHub (returns up to 30 results).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `query` | string | ✅ | Code search query (supports GitHub search syntax, e.g., `def login repo:myorg/myapp`) |

### Setup

```
Integration Settings → github → Credentials
  key: access_token     value: ghp_your-personal-access-token
```

Minimum token scopes: `repo` for private repos, `public_repo` for public only.

## Adding Built-in Tools to an Agent

### Via App Seeding (Recommended)

App Seeding is the primary way to add integration tools. It seeds all tools from `_registry.py` as `Agent Tool Function` documents.

Run from the bench:
```bash
bench execute huf.ai.app_seeding.seeder.seed_integration_tools
```

Or trigger it from the HUF workspace: **Tools → Seed Integration Tools**.

### Via Agent Tool Function Manually

1. Go to **HUF → Agent Tool Function**
2. Create or open an existing tool (tools seeded by the registry already exist)
3. Confirm `Types` is set to `Custom Function` and `Function Path` points to the handler (e.g., `huf.ai.tools.slack.handle_send_message`)
4. Open your **Agent** document
5. In the **Agent Tool** child table, add a row and link to the `Agent Tool Function`
