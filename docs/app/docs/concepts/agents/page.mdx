# Agents

An **Agent** is the central building block of Huf. It pairs an LLM model with a system prompt (instructions), a set of tools, and a behaviour configuration. When a user or trigger submits a prompt, the agent reasons through it, calls tools as needed, and returns a response.

---

## What Makes an Agent?

Every agent has four core ingredients:

| Ingredient | What it does |
|---|---|
| **Instructions** | The system prompt — defines the agent's persona, goals, constraints, and tone |
| **Provider + Model** | Which LLM to call (via LiteLLM) |
| **Tools** | Actions the agent can take: read/write Frappe docs, call APIs, run sub-agents |
| **Parameters** | Sampling settings (`temperature`, `top_p`) that control response randomness |

## Agent DocType Fields

### General Tab

| Field | Fieldname | Type | Notes |
|---|---|---|---|
| Agent Name | `agent_name` | Data | Unique identifier. Auto-named from this field. |
| Provider | `provider` | Link → AI Provider | Required. Determines API key and routing. |
| Model | `model` | Link → AI Model | Required. The model to use for inference. |
| Temperature | `temperature` | Float | 0–2. Default `1`. Lower = more deterministic. |
| Top P | `top_p` | Float | Nucleus sampling. Default `1`. Adjust one of temperature *or* top_p, not both. |
| Description | `description` | Small Text | Short summary shown in lists and the chat picker. |
| Disabled | `disabled` | Check | If checked, the agent will not run when triggered. |

### Prompt Tab

Huf supports two prompt modes, selectable via **Prompt Mode**:

- **Local** — the `instructions` field (Code/Markdown) is the system prompt. Edited directly on the agent.
- **Template** — links to an **Agent Prompt** from the prompt library. Supports versioning and locking.

| Field | Fieldname | Type | Notes |
|---|---|---|---|
| Prompt Mode | `prompt_mode` | Select | `Local` or `Template`. Default: `Local`. |
| Agent Prompt | `agent_prompt` | Link → Agent Prompt | Visible when Prompt Mode = Template. |
| Lock Prompt Version | `prompt_version_locked` | Check | If checked, agent stays on the version it was attached to. |
| Attached at Version | `template_version_at_attach` | Int | Read-only. Records the version number at time of attachment. |
| Instructions | `instructions` | Code (Markdown) | Visible when Prompt Mode = Local. The actual system prompt. |

### Prompt Caching

Huf can cache repeated prompt content to reduce token cost. Support is auto-detected using LiteLLM pricing metadata (see `prompt_cache_capabilities.py`).

| Field | Fieldname | Notes |
|---|---|---|
| Enable Prompt Caching | `enable_prompt_caching` | Master switch. Works with Anthropic, OpenAI, Deepseek. |
| Cache Control Type | `cache_control_type` | `ephemeral` (Anthropic) or `auto` (OpenAI/Deepseek). |
| Cache System Message | `cache_system_message` | Caches the instructions/system prompt block. Default: on. |
| Cache Conversation History | `cache_conversation_history` | Caches multi-turn history messages to cut repeated costs. |

### Behaviour Tab

| Field | Fieldname | Notes |
|---|---|---|
| Allow Chat | `allow_chat` | Enables the Agent Chat interface for this agent. |
| Persist Conversation | `persist_conversation` | If on, conversation history is saved and reloaded across sessions. |
| Persist per User (Doc/Schedule) | `persist_user_history` | When on, Doc Event and Scheduled runs maintain a separate history per user. When off, a single shared history is used. Default: on. |
| Enable Multi Run | `enable_multi_run` | Turns on the orchestration planner. The agent breaks work into steps and executes them sequentially. |

### Advanced Settings Tab

| Field | Fieldname | Notes |
|---|---|---|
| Context Strategy | `context_strategy` | `Summarize`, `FIFO`, or `None`. How to handle history overflow. |
| History Limit | `history_limit` | Max messages in active context before strategy is applied. Default: 20. |
| Summary Ratio | `summary_ratio` | Fraction of oldest messages to compress. Default: 0.7. |
| Summary Model | `summary_model` | Optional lightweight model for summarization. Falls back to the main model. |
| Max Knowledge Tokens | `max_knowledge_tokens` | Token budget for injected knowledge context. Default: 4000. |
| Max Turns | `max_turns` | Max consecutive tool-call/response cycles per run. Default: 20. |
| Allow Conversation Data Management | `enable_conversation_data` | Enables the agent's key-value memory store (`conversation_data`). |
| Inject Conversation Data into Prompt | `inject_conversation_data` | When on, all stored memory items are injected into every turn. Turn off to reduce context bloat and use `get_conversation_data` on-demand instead. |

### Audio / Vision

| Field | Fieldname | Notes |
|---|---|---|
| TTS Model | `tts_model` | Link → AI Model. Dedicated model for the `generate_audio` tool. When set, API key comes from the TTS model's own provider (e.g. ElevenLabs). |
| TTS Voice | `tts_voice` | Default voice identifier (e.g. `alloy`, `nova`, or an ElevenLabs voice ID). |

### Huf UI Settings

| Field | Fieldname | Notes |
|---|---|---|
| Agent Color | `agent_color` | Hex colour for the agent avatar in chat (e.g. `#6366F1`). |
| Show Tool Execution Details | `show_tool_execution_details` | If enabled, tool call status and results are shown in the chat output. |
| Autonaming of Conversation Title | `autonaming_of_conversation_title` | When on, the conversation title is auto-generated from the first few messages. |

### Permissions Tab

| Field | Fieldname | Notes |
|---|---|---|
| Allow Guest | `allow_guest` | Lets unauthenticated (Guest) users run this agent via the API. |
| Allowed Users | `allowed_users` | Table Multi-Select of specific users (via `Agent User`). If empty, any logged-in user can run the agent. |
| Allowed Roles | `allowed_roles` | Table Multi-Select of roles (via `Agent Role`). If empty, any logged-in user can run the agent. |

> [!NOTE]
> If **both** `allowed_users` and `allowed_roles` are empty, all authenticated users can use the agent. Add at least one entry to restrict access.

### Metadata Tab

| Field | Fieldname | Notes |
|---|---|---|
| Last Run | `last_run` | Datetime of the most recent execution. Read-only. |
| Total Run | `total_run` | Cumulative run count. Read-only. |

## Child Tables on Agent

### Agent Tool (`agent_tool`)

Links the agent to its `Agent Tool Function` records. Each row in this table represents one tool the agent is allowed to use. See the [Tools](/docs/tools) guide for details on defining tools.

### Agent MCP Server (`agent_mcp_server`)

Links the agent to external **MCP (Model Context Protocol) servers** for additional tool capabilities. Each row points to an `MCP Server` document and has an `enabled` flag. When enabled, all enabled tools from that MCP server are automatically wired into the agent on each run.

```
Agent  →  Agent MCP Server (child table)  →  MCP Server  →  MCP Server Tool (child table)
```

MCP tools appear alongside native tools; the agent uses them transparently.

### Agent Knowledge (`agent_knowledge`)

Links the agent to `Knowledge Source` documents (documents, PDFs, web pages, Huf Data Tables, etc.). Each row has:

| Field | Notes |
|---|---|
| `knowledge_source` | Link to the Knowledge Source |
| `mode` | `Mandatory` or `Optional` |
| `priority` | Lower number = higher priority in context building |
| `max_chunks` | Maximum retrieved chunks per source. Default: 5. |
| `token_budget` | Token cap for this source's contribution. Default: 2000. |

- **Mandatory** sources are automatically retrieved and injected into the system prompt on every run.
- **Optional** sources are exposed as a `knowledge_search` tool that the agent can call when it needs information.

### Agent Orchestration Plan (`default_plan`)

Available when **Enable Multi Run** is on. Pre-defines the steps the agent should follow for any prompt. Each row has:

| Field | Notes |
|---|---|
| `step_index` | Order of execution (1, 2, 3…) |
| `instruction` | The step instruction given to the agent |
| `status` | Runtime status: `pending`, `in_progress`, `done`, `failed` |

If `default_plan` is empty, the orchestrator auto-generates steps by sending the user prompt to a planning LLM call.

## Running Agents

### Chat Interface

Enable `allow_chat` on the agent, then navigate to **Huf → Agent Chat** and select the agent. The chat UI provides real-time markdown rendering and tool execution status.

### API

```bash
POST /api/method/huf.ai.agent_integration.run_agent_sync
Content-Type: application/json

{
  "agent_name": "My Agent",
  "prompt": "Create a sales order for Acme Corp",
  "channel_id": "api"
}
```

Response:
```json
{
  "success": true,
  "response": "Done. Sales Order SO-0001 has been created.",
  "agent_run_id": "AGR-00001",
  "conversation_id": "AGC-00001"
}
```

### Agent Console

The **Agent Console** is a singleton DocType for quick testing. Navigate to **Huf → Agent Console**, select an agent, enter a prompt, and click **Run**. The response appears in the `response` field.

### Triggers

Agents can be invoked automatically via **Agent Trigger** (Doc Events, Schedules, Webhooks, App Events). See the [Triggers](/docs/concepts/triggers) guide.

## Agent Run Logging

Every execution creates an **Agent Run** document tracking:

- Status (`Queued` → `Started` → `Success` / `Failed`)
- Input and output tokens
- Estimated cost
- Prompt and response content
- Linked conversation, flow run (if triggered from a flow), or orchestration

## Tips for Writing Good Instructions

1. **Be explicit about the agent's role** — start with "You are a…" to set context.
2. **Describe available tools** — briefly list what the agent can do so it picks the right tool.
3. **Set boundaries** — tell the agent what it should *not* do (e.g. "Do not delete records without confirmation").
4. **Specify output format** — if you need JSON, markdown tables, or bullet points, say so.
5. **Keep it focused** — agents with narrow, clear mandates perform better than catch-all agents.
6. **Use examples** — a few concrete worked examples in the prompt dramatically improve accuracy for complex tasks.
7. **Version your prompts** — use the Template mode with `Agent Prompt` to track iterations.

```
Example Instructions:
You are an Order Processing Agent for Acme Corp.

Your job is to create and update Sales Orders based on user requests.

Available tools:
- create_sales_order: Creates a new Sales Order
- update_sales_order: Updates fields on an existing Sales Order
- get_customer: Retrieves customer details

Rules:
- Always confirm the customer exists before creating an order.
- Never delete records; mark them as cancelled instead.
- Respond with a summary of what you did, in plain English.
```
