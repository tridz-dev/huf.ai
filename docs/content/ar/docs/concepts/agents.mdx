# الوكلاء

**الوكلاء هم أعضاء فريق يعملون بالذكاء الاصطناعي لموقع Frappe الخاص بك.** فكّر في كل وكيل على أنه متخصص بمهمة محددة، مزوّد بأدوات للعمل مع بياناتك، ومستعد لمساعدة المستخدمين أو أتمتة المهام.

## ما هو الوكيل؟

يتكون الوكيل في Huf من أربعة مكونات أساسية:

1. **Instructions** - "الشخصية" وتعريف الدور (system prompt)
2. **AI Model** - "العقل" (GPT-4، Claude، Gemini، إلخ)
3. **Tools** - "القدرات" (ما يمكنه فعله ببياناتك)
4. **Settings** - معاملات ضبط دقيقة (temperature، top_p)

عند تشغيل وكيل، يقوم بما يلي:
- قراءة تعليماته لفهم دوره
- استخدام نموذج الذكاء الاصطناعي للتفكير في الطلبات
- استدعاء الأدوات للتفاعل مع بيانات Frappe
- إرجاع استجابات مفيدة وسياقية

## بنية الوكيل

### Instructions (System Prompt)

أهم جزء في الوكيل. هنا تُحدّد:
- **من** هو الوكيل (الدور، الشخصية)
- **ما** الذي يمكنه المساعدة فيه (نطاق المهام)
- **كيف** يجب أن يتصرف (النبرة، الأسلوب، القيود)
- **متى** يستخدم الأدوات وكيف

**أمثلة على التعليمات:**

<AgentPrompt title="أخصائي دعم العملاء">
أنت أخصائي دعم عملاء لشركتنا القائمة على Frappe. مهمتك هي:

1. مساعدة المستخدمين في العثور على معلومات العملاء وفهمها
2. البحث عن الطلبات وحالتها
3. إنشاء تذاكر دعم عندما تحتاج المشكلات إلى التصعيد

عندما يسأل المستخدم عن عميل:
- اطلب اسم العميل أو معرّفه إذا لم يُقدَّما
- استخدم أداة get_customer لاسترجاع المعلومات
- اعرض المعلومات بوضوح وسلّط الضوء على التفاصيل الرئيسية

كن دائمًا مهذبًا ومهنيًا ومختصرًا. إذا لم تتمكن من المساعدة في أمر ما،
اشرح السبب واقترح بدائل.
</AgentPrompt>

### AI Model

النموذج يحدد ذكاء الوكيل وقدراته:

| نوع النموذج | الأفضل لـ | التكلفة | السرعة |
|------------|----------|------|-------|
| **GPT-4 Turbo** | التفكير المعقد، الاستجابات المفصلة | $$$ | متوسطة |
| **GPT-3.5 Turbo** | المهام السريعة، التفاعلات البسيطة | $ | سريعة |
| **Claude 3 Opus** | السياق الطويل، الفهم الدقيق | $$$ | متوسطة |
| **Claude 3 Sonnet** | التوازن بين الأداء والتكلفة | $$ | سريعة |
| **Gemini Pro** | متعدد الوسائط، نظام Google البيئي | $$ | سريعة |

<Callout type="info">
  ابدأ بنموذج أرخص (GPT-3.5، Gemini) للاختبار، ثم انتقل إلى نماذج أقوى (GPT-4، Claude Opus) للإنتاج إذا دعت الحاجة.
</Callout>

### Tools

الأدوات تمنح الوكلاء القدرة على التفاعل مع Frappe. بدون أدوات، لا يمكن للوكلاء سوى الدردشة — لا يمكنهم قراءة البيانات أو تعديلها.

**أنواع الأدوات المدمجة:**
- **Get Document** - جلب مستند محدد بواسطة المعرف
- **Create Document** - إنشاء مستندات جديدة
- **Update Document** - تعديل المستندات الموجودة
- **Delete Document** - حذف المستندات
- **Get List** - الاستعلام عن المستندات مع التصفية والترتيب
- **Run Agent** - الربط بوكيل آخر
- **HTTP Request** - استدعاء واجهات برمجة التطبيقات الخارجية

**أدوات مخصصة:**
- الربط بوظائف Python الخاصة بك
- تحديد المعاملات وأنواع الإرجاع
- يتم اكتشافها تلقائيًا إذا زُيّنت بـ `@agent_tool`

تعرّف على المزيد في [Tools](/docs/concepts/tools).

### Settings

ضبط سلوك الوكيل بدقة باستخدام هذه المعاملات:

**Temperature** (`0.0` - `2.0`)
- **أقل (0.0-0.3)**: أكثر تركيزًا وحتمية واتساقًا
  - الأفضل لـ: استرجاع البيانات، التحقق من الصحة، المهام المنظمة
- **متوسط (0.7)**: توازن بين الإبداع والاتساق
  - الأفضل لـ: المحادثات العامة، دعم العملاء
- **أعلى (1.0-2.0)**: أكثر إبداعًا وتنوعًا واستكشافيًا
  - الأفضل لـ: إنشاء المحتوى، العصف الذهني

**Top P** (`0.0` - `1.0`)
- بديل عن temperature (أخذ العينة النووية)
- يتحكم في تنوع اختيارات الكلمات
- ابدأ بـ `1.0` لمعظم حالات الاستخدام
- القيم الأقل تجعل المخرجات أكثر تركيزًا

<Callout type="warning">
  استخدم إما temperature أو top_p، وليس كليهما. Temperature هو الأكثر شيوعًا.
</Callout>

## حالات الوكيل

للوكلاء دورة حياة:

<div className="huf-state-row">
  {["Draft", "Active", "Running", "Completed"].map((s, i, arr) => (
    <span key={s} style={{ display: 'inline-flex', alignItems: 'center', gap: '0.5rem' }}>
      <span className="huf-state-pill">{s}</span>
      {i < arr.length - 1 && <span className="huf-state-arrow">→</span>}
    </span>
  ))}
</div>

- **Draft**: قيد التكوين، غير جاهز للاستخدام
- **Active**: جاهز للتشغيل (يدويًا، أو مجدولًا، أو مُفعّلًا)
- **Running**: يعالج طلبًا حاليًا
- **Completed**: انتهى التنفيذ (تحقق من Agent Run للنتائج)

## أنواع الوكلاء

### 1. وكلاء الدردشة

**وكلاء تفاعلية محادثة** يمكن الوصول إليها عبر Agent Chat أو واجهة `/huf` الأمامية.

**كيفية التفعيل**: حدد **Allow Chat** عند إنشاء الوكيل.

**حالات الاستخدام:**
- روبوتات دعم العملاء
- مكاتب المساعدة الداخلية
- مساعدي استكشاف البيانات
- التقارير التفاعلية

**المميزات:**
- محادثات فورية
- سجل المحادثة يُحفظ تلقائيًا
- تفاعلات متعددة الجولات مع السياق الكامل
- يمكن استخدام الأدوات بشكل ديناميكي أثناء الدردشة

**مثال**: وكيل دعم عملاء يساعد المستخدمين في البحث عن الطلبات، والتحقق من الحالة، وإنشاء التذاكر — كل ذلك من خلال محادثة طبيعية.

### 2. الوكلاء المجدولة

**وكلاء تعمل تلقائيًا** في فواصل زمنية محددة (كل ساعة، يوميًا، أسبوعيًا، إلخ).

**كيفية التكوين**: أنشئ **Agent Trigger** بجدول زمني.

**حالات الاستخدام:**
- التقارير والملخصات اليومية
- تنظيف البيانات الدوري
- فحوصات الصحة المنتظمة
- الإشعارات التلقائية

**المميزات:**
- جدولة تشبه Cron
- يمكنها العمل بدون إدخال المستخدم (قدّم prompt في المُشغّل)
- النتائج تُسجّل في Agent Run
- يمكن ربطها بوكلاء أخرى

**مثال**: وكيل ملخص المبيعات اليومي الذي يعمل كل صباح في الساعة 9 صباحًا، ويحلل طلبات الأمس، ويرسل تقريرًا عبر البريد الإلكتروني.

### 3. الوكلاء المُفعّلة بالأحداث

**وكلاء تُشغّل تلقائيًا** عند إنشاء المستندات أو تحديثها أو إرسالها أو حذفها.

**كيفية التكوين**: أنشئ **Agent Trigger** يحتوي على:
- **DocType** - نوع المستند الذي سيتم مراقبته
- **Event** - الحدث الذي سيتم التشغيل عنده (after_insert، on_submit، إلخ)
- **Condition** (اختياري) - تعبير Python لتصفية وقت التشغيل

**حالات الاستخدام:**
- التحقق من صحة المستندات قبل الإرسال
- ملء الحقول تلقائيًا بناءً على تحليل الذكاء الاصطناعي
- إشعار الفرق عند استيفاء الشروط
- إثراء البيانات عند الإنشاء

**المميزات:**
- تعمل في الخلفية تلقائيًا
- الوصول إلى المستند الذي أطلقها
- يمكن تعديل المستند أو إنشاء مستندات ذات صلة
- سجل محادثات لكل مستخدم أو مشترك

**مثال**: مدقق الفواتير الذي يعمل عند إرسال الفواتير، ويفحص الأخطاء أو الحالات الشاذة، ويضع علامات على المشكلات أو يصححها تلقائيًا.

تعرّف على المزيد في [Triggers](/docs/concepts/triggers).

### 4. وكلاء التنسيق متعدد التشغيلات

**وكلاء تقسم المهام المعقدة إلى خطوات** وتنفذها بشكل متسلسل عبر تشغيلات متعددة.

**كيفية التفعيل**: حدد **Enable Multi Run** عند إنشاء الوكيل.

**حالات الاستخدام:**
- سير العمل المعقدة متعددة الخطوات
- المهام التي تتطلب مراحل التخطيط والتنفيذ
- العمليات الطويلة التي تحتاج إلى تقدم تدريجي
- مهام البحث أو التحليل ذات المراحل المتعددة

**المميزات:**
- مرحلة تخطيط تلقائية تقسم الأهداف إلى خطوات
- تنفيذ الخطوات بشكل متسلسل عبر المجدول
- مسودة للحفاظ على السياق بين الخطوات
- تخزين كامل المخرجات لكل خطوة
- تتبع التقدم ومعالجة الأخطاء

**آلية العمل:**
1. **أول استدعاء API** → ينشئ مستند التنسيق
2. **مرحلة التخطيط** → يولّد الوكيل قائمة مرقمة بالخطوات
3. **معالجة المجدول** → ينفذ خطوة واحدة في الدقيقة
4. **الحفاظ على السياق** → تحمل المسودة المعلومات بين الخطوات
5. **الإنجاز** → يُعلّم على أنه مكتمل عند الانتهاء من جميع الخطوات

**مثال**: وكيل بحث المحتوى الذي:
1. يحدد الموضوعات المستهدفة
2. يجمع المعلومات ذات الصلة
3. يحلل النتائج
4. ينشئ مخططًا تفصيليًا
5. يكتب مسودة المحتوى
6. يراجعها ويحسّنها

تعرّف على المزيد في [Running Agents - Multi-Run Orchestration](/docs/guides/running-agents#multi-run-orchestration).

### اختيار الأدوات

- **ابدأ بأدوات أساسية**: أضف فقط الأدوات الأساسية في البداية
- **اختبر بشكل شامل**: تحقق من أن كل أداة تعمل بشكل صحيح
- **أوصاف الأدوات مهمة**: يستخدمها الذكاء الاصطناعي لتحديد وقت استدعاء الأدوات
- **لا تُكثّر**: الكثير من الأدوات يُربك النموذج (احتفظ بحوالي 5-10)
- **جمّع حسب الغرض**: أنشئ وكلاء متخصصة بدلًا من وكيل ضخم واحد

### ضبط الأداء

**للحصول على مخرجات متسقة:**
- **تقليل temperature** (0.0-0.3)
- تعليمات أكثر تحديدًا
- قدّم أمثلة في التعليمات

**للحصول على مخرجات إبداعية:**
- **رفع temperature** (0.8-1.5)
- تعليمات أقل تشددًا
- شجّع على الاستكشاف

**لتحسين التكلفة:**
- استخدم نماذج أرخص للمهام البسيطة
- حدّد طول سجل المحادثة
- اكتب تعليمات مختصرة (أقل tokens)
- خزّن الاستعلامات المتكررة

## إدارة الوكلاء

### عرض جميع الوكلاء

انتقل إلى: **Desk → Huf → Agent**

- شاهد جميع الوكلاء في طريقة العرض قائمة
- صفّي حسب الحالة أو النموذج أو الحقول الأخرى
- انقر على وكيل لتحريره أو عرض تفاصيله

### تحرير الوكلاء

تدخل تغييرات الوكلاء حيز التنفيذ فورًا للتشغيلات الجديدة. قد تستخدم المحادثات الجارية أو التشغيلات المجدولة التكوين القديم حتى تكتمل.

<Callout type="info">
  اختبر التغييرات في وكيل مسودة/مكرر قبل تعديل وكلاء الإنتاج.
</Callout>

### مراقبة الأداء

تحقق من **Agent Run** لكل تنفيذ:
- عرض prompts والاستجابات
- رؤية استدعاءات الأدوات ونتائجها
- تتبع استخدام tokens والتكاليف
- تحديد الأخطاء والمشكلات

تعرّف على المزيد في [Monitoring](/docs/monitoring).

### الصلاحيات

يرث الوكلاء صلاحيات المستخدم الذي يشغلهم. لا يستطيع الوكيل:
- الوصول إلى مستندات لا يملك المستخدم إذنًا لها
- إنشاء مستندات في DocTypes لا يستطيع المستخدم الوصول إليها
- تجاوز نموذج أمان Frappe

اضبط الصلاحيات عبر **Role Permission Manager** في Frappe.

## الأنماط الشائعة

### وكيل دعم العملاء

**Role**: مساعدة المستخدمين في استفسارات العملاء

**Tools**:
- Get Customer
- Get List (Sales Orders, Support Tickets)
- Create Support Ticket

**Instructions**: ركّز على أن تكون مفيدًا، واطرح أسئلة توضيحية، وصعّد المشكلات المعقدة.

### مدقق المستندات

**Role**: التحقق من صحة المستندات قبل الإرسال

**Trigger**: حدث `on_submit` لـ DocType المستهدف

**Tools**:
- Get Document
- Update Document
- Get List (للبيانات المرجعية)

**Instructions**: تحقق من الحقول المحددة، وتحقق من القواعد، وضع علامات أو صحّح المشكلات تلقائيًا.

### المراسل المجدول

**Role**: إنشاء تقارير دورية

**Trigger**: يوميًا في الساعة 9 صباحًا

**Tools**:
- Get List (مع مرشحات التاريخ)
- دالة مخصصة لإرسال بريد إلكتروني/Slack

**Instructions**: لخّص البيانات، وسلّط الضوء على الرؤى، ونسّقها لتكون سهلة القراءة.

### مساعد إدخال البيانات

**Role**: مساعدة المستخدمين في إنشاء المستندات تفاعليًا

**Tools**:
- Create Document
- Get List (للبحث)
- Get Document (للتحقق)

**Instructions**: دلّل المستخدمين عبر الحقول المطلوبة، تحقق من المدخلات، وأنشئ المستندات.

## استكشاف الأخطاء وإصلاحها

### الوكيل لا يستجيب

**تحقق من:**
- صلاحية مفتاح API وتوفر الرصيد
- صحة اسم النموذج لمزود الخدمة
- عدم كون التعليمات فارغة
- حفظ كل من المزود والنموذج

**تصحيح:**
- انظر إلى **Agent Run** لرسائل الخطأ
- اختبر مفتاح API بشكل مستقل
- جرّب نموذجًا آخر

### الأدوات لا تعمل

**تحقق من:**
- إضافة الأداة إلى قائمة أدوات الوكيل
- وضوح ودقة وصف الأداة
- امتلاك المستخدم صلاحيات الـ DocType
- صحة معاملات الأداة

**تصحيح:**
- اختبر الأداة بشكل مستقل في Python
- تحقق من **Agent Run** لرؤية استدعاءات الأدوات
- تحقق من الصلاحيات عبر Role Permission Manager

### استجابات ضعيفة

**حسّن:**
- اجعل التعليمات أكثر تحديدًا
- أضف أمثلة على الاستجابات الجيدة
- قلّل temperature لمزيد من الاتساق
- بسّط المهمة أو قسّمها إلى وكلاء متعددة
- راجع سجلات Agent Run لترى ما يفكر فيه الوكيل

### تكاليف مرتفعة

**حسّن:**
- استخدم نماذج أرخص (GPT-3.5 مقابل GPT-4)
- اختصر التعليمات (أقل tokens للإدخال)
- حدّد طول سجل المحادثة
- قلّل أوصاف الأدوات
- خزّن الاستعلامات المتكررة
- راجع **Agent Run** لتحديد العمليات المكلفة
