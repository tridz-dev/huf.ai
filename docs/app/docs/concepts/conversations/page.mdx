# Conversations & Memory

Huf tracks every interaction between users and agents using a three-layer structure: **Conversations**, **Messages**, and **Runs**. On top of this, agents can maintain a persistent key-value **memory store** per conversation.

---

## Agent Conversation DocType

A conversation groups all messages from a continuous session between a user and an agent.

| Field | Fieldname | Type | Notes |
|---|---|---|---|
| Title | `title` | Data | Auto-generated or set from the first message. Can be renamed. |
| Agent | `agent` | Link → Agent | The agent this conversation belongs to. |
| Session ID | `session_id` | Data | Unique key combining channel and user/external ID. Used to resume the right conversation. |
| Is Active | `is_active` | Check | Indicates if the conversation is ongoing. |
| Total Messages | `total_messages` | Int | Running count of all messages (read-only). |
| Conversation Data | `conversation_data` | JSON | Key-value memory store. See [Conversation Data](#conversation-data-memory) below. |

### Session Identification

Huf maps users and channels to conversations using a `session_id`. The session ID is composed as:

```
{channel_id}:{external_id}
```

- `channel_id` — the origin of the request (e.g. `chat`, `doc_event`, `api`, `webhook`).
- `external_id` — the user identifier or scope key.

When `persist_user_history` is **on** (the default for Doc Event / Schedule triggers), the `external_id` is the initiating user's email. When it's **off**, a shared key like `shared:{agent_name}` is used so all runs share one conversation.

## Agent Message DocType

A message is a single turn in a conversation — a user input, agent response, tool call, or tool result.

| Field | Fieldname | Type | Notes |
|---|---|---|---|
| Conversation | `conversation` | Link | Parent conversation. |
| Role | `role` | Select | `user`, `agent`, `tool`, or `system`. |
| Kind | `kind` | Select | `Message`, `Tool Call`, `Tool Result`, `Status`, `Error`, `Image`, `Audio`. |
| Content | `content` | Code (Markdown) | Text content of the message. |
| Content Type | `content_type` | Select | `Text`, `JSX`, `Mermaid`, `Markdown`, `Artifact`, `HTML`, `Image`. Controls frontend rendering. |
| Agent Run | `agent_run` | Link → Agent Run | The run that generated this message. |
| Session ID | `session_id` | Data | Copied from the conversation for fast filtering. |
| Conversation Index | `conversation_index` | Int | Position of this message in the conversation (0-based). |
| Is Agent Message | `is_agent_message` | Check | True if this message was generated by the agent (not the user). |
| Generated Image | `generated_image` | Attach Image | Populated for `kind = Image` messages. |
| Generated Audio | `generated_audio` | Attach | Populated for `kind = Audio` messages. |
| TTS Model | `tts_model` | Link → AI Model | Model used for audio synthesis in this message. |
| TTS Voice | `tts_voice` | Data | Voice identifier used (e.g. `alloy`, `nova`). |
| STT Model | `stt_model` | Link → AI Model | Model used for speech-to-text if applicable. |
| Voice Message | `voice_message` | Attach | Original audio file from the user (for STT). |

### Tool Call Details

When `kind = Tool Call` or `kind = Tool Result`, the message links to an **Agent Tool Call** document:

| Field | Notes |
|---|---|
| `tool_calll` | Link to Agent Tool Call |
| `tool_name` | Fetched from the tool call — tool that was invoked |
| `tool_args` | JSON arguments passed to the tool |
| `tool_status` | Result status (success/error) |

## Agent Run DocType

An Agent Run captures one complete reasoning cycle — from the moment a prompt is received to the moment the agent returns its final response (including all tool calls in between).

| Field | Fieldname | Notes |
|---|---|---|
| Conversation | `conversation` | Parent conversation |
| Agent | `agent` | Agent that ran |
| Status | `status` | `Started` → `Queued` → `Success` / `Failed` |
| Prompt | `prompt` | The input prompt |
| Response | `response` | The agent's final text response |
| Error Message | `error_message` | Populated if status = Failed |
| Error Code | `error_code` | Machine-readable error code |
| Input Tokens | `input_tokens` | Tokens fed into the model |
| Output Tokens | `output_tokens` | Tokens in the model response |
| Cached Tokens | `cached_tokens` | Tokens served from prompt cache (reduces cost) |
| Cost | `cost` | Estimated cost in USD |
| Start Time | `start_time` | Timestamp before API call |
| End Time | `end_time` | Timestamp after response is fully streamed |
| Provider | `provider` | Provider used for this run |
| Model | `model` | Model used for this run |
| Parent Run | `parent_run` | Set for child runs (orchestration steps or sub-agents) |
| Is Child | `is_child` | True if this run was spawned by another run |
| Agent Orchestration | `agent_orchestration` | Link to the orchestration document if multi-step |
| Prompt Template | `prompt_template` | Link to Agent Prompt if a template was used |
| Run Kind | `run_kind` | `agent`, `tool`, or `orchestrator` |
| Flow Run | `flow_run` | Link to the Flow Run that spawned this run (if triggered from a Flow) |
| Flow Node ID | `flow_node_id` | Which node in the flow triggered this run |

## Conversation Data (Memory)

The **conversation data** store is a per-conversation key-value dictionary persisted in `Agent Conversation.conversation_data` as JSON.

Agents can read and write to this store using built-in tools:

| Tool | What it does |
|---|---|
| `set_conversation_data(name, value)` | Store a named value |
| `get_conversation_data(name, default)` | Retrieve a named value |
| `load_conversation_data()` | Load the full memory state |

### Data Item Structure

Each item in the store has:

```json
{
  "name": "customer_name",
  "value": "Acme Corp",
  "meta": {
    "type": "scalar",
    "updated_at": "2025-10-01T12:00:00+00:00",
    "source": "agent"
  },
  "auto_inject": true,
  "inject_mode": "visible"
}
```

- **`auto_inject`** — when `true` and **Inject Conversation Data into Prompt** is enabled on the agent, this item is automatically included in every prompt as context.
- **`inject_mode`** — `visible` (shown in the conversation as context) or `hidden` (injected silently into the system prompt only).

### Enabling Memory

On the **Agent** form, Advanced Settings tab:

| Setting | Notes |
|---|---|
| Allow Conversation Data Management | Master switch. Enables the `get/set_conversation_data` tools. |
| Inject Conversation Data into Prompt | When on, `auto_inject` items are embedded in every request. Turn off and use `get_conversation_data` on demand to reduce token usage. |

### Example Usage in a Conversation

```
User: Remember that my preferred currency is GBP.
Agent: [calls set_conversation_data("preferred_currency", "GBP")]
       Noted! I'll remember that your preferred currency is GBP.

User: Create an invoice for £500.
Agent: [auto_inject inserts: "preferred_currency = GBP"]
       [calls create_document("Sales Invoice", {..., currency: "GBP"})]
       Done. Invoice SI-0001 created for £500.00 (GBP).
```

## Conversation History Management

For long-running conversations, the agent's effective context window is bounded by the model's token limit. Huf provides three **context strategies** to manage history overflow:

| Strategy | How it works |
|---|---|
| `None` | All history is included. Best for short conversations or large context models. |
| `FIFO` | The oldest messages are dropped to make room. Simple and fast. |
| `Summarize` | The oldest N messages (controlled by `summary_ratio`) are compressed into a short summary by an LLM call. The summary is injected as a system message. |

Configure per-agent via **Advanced Settings → Context Strategy**, **History Limit**, **Summary Ratio**, and **Summary Model**.

## Conversation Feedback

Users can leave **thumbs up / thumbs down** feedback on individual agent messages. Feedback is stored in the **Agent Run Feedback** DocType:

| Field | Notes |
|---|---|
| `feedback` | `Thumbs Up` or `Thumbs Down` |
| `comments` | Optional text comment |
| `agent_message` | The message being rated |
| `agent` | The agent that produced the message |
| `provider` / `model` | Auto-fetched from the agent |

Feedback data can be exported for fine-tuning or quality analysis.

## API Access

### Listing Conversations

```bash
GET /api/resource/Agent Conversation?filters=[["agent","=","My Agent"]]
```

### Listing Messages in a Conversation

```bash
GET /api/resource/Agent Message?filters=[["conversation","=","AGC-00001"]]&order_by=conversation_index asc
```

### Getting Full Conversation Data

```bash
GET /api/method/huf.ai.agent_chat.get_agent_chat_messages?conversation_id=AGC-00001
```
