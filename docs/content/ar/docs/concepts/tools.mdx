# الأدوات

الأدوات هي ما تجعل الوكلاء مفيدين. بدون أدوات، يستطيع الوكيل فقط المحادثة. باستخدام الأدوات، يمكن للوكلاء قراءة البيانات، وإنشاء السجلات، واستدعاء واجهات البرمجة، وتشغيل سير العمل، وأكثر من ذلك.

## ما هي الأدوات؟

**الأدوات** هي دوال يستطيع الوكلاء استدعاؤها للتفاعل مع نظام Frappe الخاص بك أو الخدمات الخارجية. فكّر فيها باعتبارها يدي الوكيل—فهي تُمكّنه من التصرف، وليس مجرد المحادثة.

يوضّح الجدول التالي نوع العمل الذي يقوم به الوكلاء عن طريق استدعاء الأدوات:

| حالة الاستخدام | الأداة المستخدمة |
|---|---|
| البحث عن عميل | **Get Document** |
| إنشاء تذكرة دعم | **Create Document** |
| التحقق من مستويات المخزون | **Get List** |
| إرسال إشعار | **HTTP Request** أو دالة مخصصة |

يقرر الوكيل الأداة التي سيتم استخدامها بناءً على المحادثة وأوصاف الأدوات.

## كيف تعمل الأدوات؟

### تدفق تنفيذ الأداة

يتبع كل استدعاء أداة حلقة متوقعة بين المستخدم والوكيل والنظام المستهدف. فهم هذا التدفق يساعد عند تصحيح الأخطاء لمعرفة سبب قيام الوكيل أو عدم قيامه باستخدام أداة.

### اختيار الأداة

يختار الوكلاء الأدوات عن طريق مطابقة طلب المستخدم مع بيانات كل أداة. تعتمد جودة هذا القرار بشكل كامل تقريبًا على وضوح وصف الأداة.

| العامل | سبب أهميته |
|---|---|
| **اسم الأداة** | معرّف وصفي يساعد الوكيل على تضييق الخيارات بسرعة. |
| **وصف الأداة** | يشرح ما تفعله الأداة؛ وهذا أهم مؤشر لاختيارها. |
| **معاملات الأداة** | تحدد المدخلات التي تحتاجها الأداة ليعرف الوكيل ما إذا كان بإمكانه تلبية الطلب. |
| **السياق** | المحادثة الحالية وطلب المستخدم يحددان الأداة المناسبة في الوقت الحالي. |

<Callout type="warning">
  اكتب أوصاف أدوات واضحة ومحددة. يستخدمها الوكيل لتحديد متى يستخدم كل أداة.
</Callout>

## أنواع الأدوات

توفر Huf ثلاث فئات من الأدوات:

### 1. الأدوات المدمجة

الأدوات المدمجة مهيأة مسبقًا للعمليات الشائعة في Frappe. وهي تغطي دورة حياة المستند وبعض إجراءات الأدوات، بحيث يمكن تجميع معظم الوكلاء دون كتابة أي كود مخصص.

| نوع الأداة | الغرض | مثال على حالة الاستخدام |
|-----------|---------|------------------|
| **Get Document** | جلب مستند واحد بالاسم/المعرف | "أرني العميل CUST-001" |
| **Create Document** | إنشاء مستند جديد | "أنشئ عميلًا محتملًا جديدًا لشركة ABC Corp" |
| **Update Document** | تعديل مستند موجود | "حدّث بريد العميل الإلكتروني" |
| **Delete Document** | حذف مستند | "احذف أمر المسودة SO-2024-001" |
| **Submit Document** | تقديم DocType قابل للتقديم | "قدّم الفاتورة" |
| **Get List** | الاستعلام عن مستندات متعددة | "اسرد جميع تذاكر الدعم المفتوحة" |
| **Run Agent** | الربط بوكيل آخر | "اسأل وكيل المبيعات حول هذا" |
| **HTTP Request** | استدعاء واجهات برمجة خارجية | "أرسل إلى webhook Slack" |

### 2. الأدوات المخصصة

الأدوات المخصصة هي دوال Python الخاصة بك والتي تُعرّض للوكلاء. تتيح لك توسيع المنصة بما يتجاوز العمليات المدمجة مع الحفاظ على تجربة الوكيل المتسقة.

| الخاصية | كيفية العمل |
|---|---|
| **تعريف في Frappe** | إنشاء الأداة عبر نوع المستند Agent Tool Function. |
| **الربط بالدوال** | توجيه الأداة إلى مسار `module.function` الخاص بك. |
| **تحديد المعاملات** | تحديد المدخلات وأنواعها ليعرف الوكيل ما يجب تقديمه. |
| **التنفيذ التلقائي** | تتولى Huf استدعاء دالتك عندما يستدعي الوكيل الأداة. |

**مثال:**
```python
def calculate_discount(customer_type, order_total):
    """Calculate discount based on customer type and order total."""
    if customer_type == "Wholesale":
        return order_total * 0.15
    elif order_total > 10000:
        return order_total * 0.10
    else:
        return order_total * 0.05
```

### 3. الأدوات المكتشفة

الأدوات المكتشفة هي دوال يتم اكتشافها تلقائيًا من تطبيقات Frappe الخاصة بك. تقلل من جهد الإعداد لأنها تُسجّل تلقائيًا ويمكن إعادة استخدامها عبر المشاريع.

- استخدم **زخرفة `@agent_tool`** في كود تطبيقك للإشارة إلى أن الدالة هي أداة.
- يتم **المزامنة التلقائية** للأدوات عند تثبيت التطبيق.
- **لا يوجد إعداد يدوي** مطلوب بعد وضع الزخرفة.
- يمكن **مشاركة** الأدوات عبر المشاريع لأنها تأتي مع التطبيق.

راجع [نشر الأدوات](/docs/tools/publishing) للتفاصيل.

## إعداد الأداة

### نوع المستند Agent Tool Function

تُعرّف الأدوات في **Desk → Huf → Agent Tool Function**. يستوعب نوع المستند هذا كل ما يحتاجه الوكيل لاستدعاء الأداة بشكل صحيح.

**الحقول الرئيسية:**

| الحقل | الوصف |
|-------|-------------|
| **اسم الأداة** | معرّف فريد (مثل `get_customer`) |
| **الوصف** | ما تفعله الأداة (يستخدمها الذكاء الاصطناعي للاختيار) |
| **الأنواع** | فئة الأداة (Get Document، Create Document، Custom Function، إلخ) |
| **DocType المرجعي** | بالنسبة لأدوات DocType، المستند المستهدف |
| **مسار الدالة** | بالنسبة للأدوات المخصصة، مسار دالة Python |
| **المعاملات** | جدول المعلمات المدخلة مع الأسماء والأنواع والأوصاف |

### إضافة الأدوات إلى الوكلاء

بمجرد الإنشاء، يجب تعيين الأداة صراحةً لوكيل قبل أن يتمكن من استخدامها. هذه الخطوة هي أيضًا البوابة الأمنية الرئيسية للوصول إلى الأدوات.

**في نوع المستند Agent:**
1. انتقل إلى جدول **Agent Tool**.
2. انقر **Add Row**.
3. اختر **Tool Function** من القائمة المنسدلة.
4. **احفظ** الوكيل.

يمكن للوكلاء استخدام الأدوات المُعيّنة لهم صراحةً فقط.

## معاملات الأداة

يمكن للأدوات قبول معاملات يملأها الوكيل بناءً على المحادثة. المعاملات المُعرّفة بشكل جيد هي الفارق بين أداة تعمل بموثوقية وأداة يستدعيها الوكيل بشكل غير صحيح.

### تعريف المعامل

بالنسبة لكل معامل، حدّد الحقول أدناه حتى يفهم الوكيل بالضبط ما يجب تقديمه.

| الحقل | الغرض |
|---|---|
| **اسم المعامل** | اسم المتغير الذي تستقبله الدالة (مثل `customer_id`). |
| **النوع** | نوع البيانات: String، Int، Float، Boolean، Object، أو Array. |
| **الوصف** | ما يمثله هذا المعامل وكيفية تحديد القيمة الصحيحة. |
| **مطلوب** | ما إذا كان الوكيل يجب أن يقدم قيمة لتشغيل الأداة. |

### مثال: أداة Get Document

يوضّح المقتطف أدناه كيفية الإعلان عن أداة Get Document بسيطة. يستخدم الوكيل هذا الإعلان لتحديد متى يستدعي الأداة والوسيط الذي يجب تمريره.

```json
{
  "name": "get_customer",
  "description": "Retrieve detailed information about a customer",
  "parameters": [
    {
      "name": "customer_id",
      "type": "String",
      "description": "The customer ID or name",
      "required": true
    }
  ]
}
```

**سلوك الوكيل:**

- يقول المستخدم: "أرني معلومات CUST-001".
- يستخرج الوكيل `customer_id = "CUST-001"`.
- يستدعي الوكيل `get_customer("CUST-001")`.

## تفاصيل الأدوات المدمجة

### Get Document

تجلب أداة Get Document مستندًا واحدًا بالاسم أو المعرف. استخدمها عندما يشير المستخدم إلى سجل معين ويحتاج الوكيل إلى تفاصيله الكاملة.

**المعاملات:**

| المعامل | الوصف |
|---|---|
| `doctype` | اسم DocType. |
| `name` | اسم/معرف المستند. |

**الإرجاع:** المستند الكامل بجميع حقوله.

**مثال:**

<ToolCallResult
  call={`get_document(doctype="Customer", name="CUST-001")`}
  result={`{ "name": "CUST-001", "customer_name": "ABC Corp", ... }`}
/>

### Create Document

تنشئ أداة Create Document مستندًا جديدًا من مجموعة قيم الحقول. هي الخيار الصحيح عندما يطلب المستخدم إضافة سجل بدلًا من تحديث سجل موجود.

**المعاملات:**

| المعامل | الوصف |
|---|---|
| `doctype` | اسم DocType. |
| `fields` | كائن بقيم الحقول. |

**الإرجاع:** المستند المنشأ.

**مثال:**
```
Agent Call: create_document(
  doctype="Lead",
  fields={
    "lead_name": "John Doe",
    "company_name": "XYZ Inc",
    "email_id": "john@xyz.com"
  }
)
```

### Update Document

تعدّل أداة Update Document مستندًا موجودًا. استخدمها عندما يريد المستخدم تغيير حقول معينة في سجل معروف.

**المعاملات:**

| المعامل | الوصف |
|---|---|
| `doctype` | اسم DocType. |
| `name` | اسم/معرف المستند. |
| `fields` | كائن بقيم الحقول المراد تحديثها. |

**الإرجاع:** المستند المُحدّث.

### Get List

تستعلم أداة Get List عن مستندات متعددة مع التصفية والفرز والتقسيم إلى صفحات. وهي مفيدة كلما طلب المستخدم مجموعة من السجلات بدلًا من سجل واحد.

**المعاملات:**

| المعامل | الوصف |
|---|---|
| `doctype` | اسم DocType. |
| `filters` | شروط التصفية (اختياري). |
| `fields` | الحقول المراد إرجاعها (اختياري). |
| `order_by` | ترتيب الفرز (اختياري). |
| `limit` | الحد الأقصى لعدد النتائج (اختياري). |

**الإرجاع:** مصفوفة من المستندات.

**مثال:**

<ToolCallResult
  call={`get_list(
  doctype="Support Ticket",
  filters={"status": "Open", "priority": "High"},
  order_by="creation desc",
  limit=10
)`}
  result={`[ {...}, {...}, ... ]`}
/>

### Run Agent

تربط أداة Run Agent بوكيل آخر للمهام المتخصصة. تتيح لك إبقاء كل وكيل مركّز مع التعامل مع الطلبات المتعددة المجالات في محادثة واحدة.

**المعاملات:**

| المعامل | الوصف |
|---|---|
| `agent_name` | اسم الوكيل المراد تشغيله. |
| `prompt` | الرسالة المراد إرسالها إلى ذلك الوكيل. |

**الإرجاع:** رد الوكيل الآخر.

**حالة الاستخدام:** توجيه العمل إلى وكلاء متخصصين لمجالات مختلفة:

- الوكيل الرئيسي → وكيل المبيعات (لأسئلة المبيعات)
- الوكيل الرئيسي → وكيل الدعم (للمشكلات التقنية)

## الأذونات والأمان

### سياق تنفيذ الأداة

تنفذ الأدوات بأذونات **المستخدم** الذي قام بتشغيل الوكيل. هذا يبقي الوكيل ضمن حدود التفويض نفسها كمستخدم Frappe عادي.

| المبدأ | ما يعنيه |
|---|---|
| **المستخدم يشغّل الوكيل** | تعمل الأداة كذلك المستخدم. |
| **لا يمكن للوكيل تجاوز الأذونات** | إذا لم يتمكن المستخدم من قراءة Customers، فلن يتمكن الوكيل أيضًا. |
| **تُطبّق أذونات Frappe** | يتم فرض التحكم في الوصول القائم على الأدوار القياسي. |

### أفضل ممارسات الأمان

اتبع هذه الممارسات للحفاظ على قدرات الوكيل متوافقة مع ما يحتاجه كل مستخدم وكليل فعليًا.

1. **أقل الامتيازات**: عيّن فقط الأدوات الضرورية لكل وكيل.
2. **التحقق من المدخلات**: يجب أن تقوم الدوال المخصصة بالتحقق من المعاملات قبل التصرف بناءً عليها.
3. **سجلات التدقيق**: يتم تسجيل جميع استدعاءات الأدوات في Agent Run للمراجعة.
4. **فحوصات الأذونات**: تحترم الأدوات نظام أذونات Frappe افتراضيًا.
5. **عدم التصعيد**: لا يمكن للوكلاء تصعيد الأذونات إلى ما هو أعلى من أذونات المستخدم الذي قام بتشغيلهم.

<Callout type="warning">
  الوكيل الذي يمتلك أداة "Delete Document" يمكنه حذف المستندات التي يملك المستخدم الحالي إذنًا لحذفها فقط. الوكلاء ليسوا تجاوزًا أمنيًا.
</Callout>

## أداء الأداة

### تحسين استدعاءات الأدوات

كل أداة مُعيّنة لوكيل تضيف عبء قرار ورموز. إبقاء مجموعة الأدوات ضيّقة يحسّن السرعة والدقة معًا.

- **قلل عدد الأدوات**: عيّن فقط الأدوات التي من المتوقع فعلًا أن يستخدمها الوكيل.
- **أوصاف واضحة**: ساعد الوكلاء على الاختيار بشكل صحيح من المرة الأولى، وتجنب الاستدعاءات المتكررة.
- **استعلامات فعالة**: استخدم عوامل التصفية في Get List لتقليل نقل البيانات.
- **الدفعات عند الإمكان**: جمّع العمليات المتشابهة في دوال مخصصة بدلًا من إجراء العديد من الاستدعاءات الصغيرة.

### تكاليف استدعاء الأداة

تؤثر استدعاءات الأدوات على تكاليف الوكيل بعدة طرق ملموسة. الوعي بها يسهل التحكم في استخدام الرموز.

- **تعريفات الأدوات** تضيف رموزًا إلى الموجه.
- **نتائج الأدوات** تضيف رموزًا إلى المحادثة.
- **المزيد من الأدوات** يعني المزيد من الرموز، وبالتالي تكلفة أعلى.

**نصائح التحسين:**

- عيّن فقط الأدوات ذات الصلة لكل وكيل.
- استخدم أنواع DocType محددة بدلًا من الأدوات العامة للغاية.
- أرجع فقط الحقول المطلوبة في Get List.
- اجعل أوصاف الأدوات موجزة ولكن واضحة.

### تصميم الأداة

### تعيين الأدوات

عيّن الأدوات بشكل استراتيجي بحيث يملك كل وكيل بالضبط القدرات التي يحتاجها ولا أكثر. الوكلاء المتخصصون عمومًا أكثر موثوقية من الوكلاء متعددي الأغراض.

**التعيين الاستراتيجي:**

- أعط الوكلاء فقط الأدوات التي يحتاجونها.
- أنشئ وكلاء متخصصين بمجموعات أدوات مركزة.
- استخدم ربط الوكلاء للمهام المتعددة المجالات.
- اختبر بأدوات أساسية، ثم أضف حسب الحاجة.

### توثيق الأدوات

التوثيق الجيد داخل الدوال المخصصة يحسّن سلوك الوكيل مباشرة، لأن Huf تستخدم docstrings وأوصاف المعاملات كجزء من بيانات الأداة الوصفية.

عند إنشاء أدوات مخصصة:

- اكتب **docstring للدالة**؛ فهو يصبح جزءًا من وصف الأداة.
- أضف **أوصاف المعاملات** حتى يفهم الوكيل المدخلات.
- أدرج **تعليقات قيمة الإرجاع** لتوضيح ما سيتلقاه الوكيل.
