# الواجهات: الواجهة الأمامية مقابل Desk

يوفر Huf **واجهتين منفصلتين** للتفاعل مع وكلاء الذكاء الاصطناعي. فهم وقت استخدام كل منهما أمر أساسي للاستفادة القصوى من Huf.

## نظرة عامة

يلخص الجدول أدناه الواجهتين، وأين تصل إليهما، ومن صُممت كل منهما، ومدى نضجها حاليًا.

| الواجهة | الرابط | صُممت لـ | حالة الاستخدام | الحالة |
|-----------|-----|--------------|----------|--------|
| **الواجهة الأمامية** | `/huf` | المستخدمين النهائيين | الدردشة، والتفاعل مع الوكلاء، وعرض المحادثات | **تتوسع بنشاط** |
| **Desk** | `/app` | المسؤولين | تكوين الوكلاء، وإدارة المزودين، ورصد كل النشاط | **مكتملة** |

## الواجهة الأمامية (`/huf`)

الواجهة الأمامية هي تجربة الدردشة للمستخدم النهائي: مكان مركّز للتحدث مع الوكلاء دون فتح Frappe Desk بالكامل.

### ما هي

الواجهة الأمامية هي واجهة موجهة للمستخدم، ومحسّنة للدردشة مع الوكلاء وعرض المعلومات المتعلقة بهم دون الدخول إلى Frappe Desk.

**الوصول**: انتقل إلى `https://your-site.com/huf`

### من هي لهم

استخدم الواجهة الأمامية لأي شخص يحتاج إلى واجهة دردشة بسيطة دون الوصول الكامل إلى Desk. وهي مناسبة بشكل خاص للمستخدمين النهائيين، والمستخدمين غير الإداريين، والتفاعلات الموجهة للعملاء عند تكوين الأذونات بشكل صحيح.

### الإمكانيات الحالية

تغطي الواجهة الأمامية حاليًا احتياجات الدردشة الأساسية وستنمو بسرعة. يوضح الجدول أدناه ما هو متاح الآن وما هو على خارطة الطريق قريبًا.

| الإمكانية | الحالة |
|---|---|
| الدردشة الفورية مع الوكلاء | متاح الآن |
| عرض سجل المحادثات | متاح الآن |
| جلسات خاصة بالمستخدم | متاح الآن |
| استكشاف/تصفح الوكلاء | قريبًا |
| استدعاء الأدوات السريع | قريبًا |
| إدارة المحادثات | قريبًا |
| عروض مُحسّنة للجوال | قريبًا |
| المحادثات المشتركة | قريبًا |
| لوحات معلومات المستخدم | قريبًا |

### متى تستخدم الواجهة الأمامية

استخدم `/huf` عندما يكون الهدف هو تجربة دردشة نظيفة ومركّزة للمستخدمين الذين لا يحتاجون إلى تدريب على Frappe Desk—مثل تفاعلات الوكلاء مع العملاء أو الفريق—أو عندما ترغب في إبقاء التجربة بسيطة وخالية من التعقيد.

### القيود الحالية

لأن الواجهة الأمامية **قيد التطوير النشط**، فهي محدودة حاليًا بالتفاعلات عبر الدردشة، ولا تعرض تكوين الوكيل، ولا تُظهر بعد كل ميزات الوكيل.

<Callout type="info">
  **خارطة الطريق**: تتوسع الواجهة الأمامية بسرعة. نُضيف استعراض الوكلاء، واختصارات الأدوات، وإدارة المحادثات، والمزيد. تحقق من مستودع GitHub للحصول على آخر التحديثات.
</Callout>

## واجهة Desk (`/app`)

Desk هي العمود الفقري الإداري لـ Huf، حيث يتم تكوين الوكلاء والمزودين والأدوات والمراقبة.

### ما هي

**Desk** هي واجهة إدارة Frappe الكاملة حيث تُكوّن وتُدير وتراقب كل شيء في Huf.

**الوصول**: انتقل إلى `https://your-site.com/app` ← انتقل إلى مساحة عمل **Huf**

### من هي لهم

تم بناء Desk للمسؤولين الذين يُعدّون الوكلاء، والمطورين الذين يُنشئون أدوات مخصصة، وفرق العمليات التي تراقب أداء الوكلاء، وأي شخص يحتاج إلى تحكم ورؤية كاملين.

### الإمكانيات الكاملة

ينقسم عمل Desk إلى ثلاثة مجالات: التكوين، والمراقبة، والإدارة. يسرد الجدول أدناه ما يمكنك فعله في كل مجال.

| الإمكانية | الفئة | الغرض |
|---|---|---|
| إنشاء الوكلاء وتحريرهم | تكوين | بناء وصيانة تعريفات الوكلاء |
| إعداد مزودي ونماذج الذكاء الاصطناعي | تكوين | الاتصال بخدمات الذكاء الاصطناعي وإتاحة النماذج |
| تعريف أدوات ودوال الوكيل | تكوين | منح الوكلاء إمكانيات قابلة للاستدعاء |
| تكوين المشغلات (جدولة، أحداث المستندات) | تكوين | تشغيل الوكلاء حسب الجداول أو تغييرات المستندات |
| إدارة الأذونات | تكوين | التحكم في من يمكنه استخدام أو تعديل الوكلاء |
| سجلات تشغيل الوكيل (كل تنفيذ) | مراقبة | فحص كل تنفيذ للوكيل |
| سجل المحادثات (جميع المستخدمين) | مراقبة | مراجعة الدردشات عبر النظام |
| استخدام الرموز والتكاليف | مراقبة | تتبع الإنفاق |
| تفاصيل استدعاء الأدوات | مراقبة | رؤية الأدوات التي تم استدعاؤها بالتحديد |
| تتبع الأخطاء | مراقبة | اكتشاف الأعطال وتصحيحها |
| أذونات المستخدمين للوكلاء | إدارة | تعيين الوصول لكل وكيل |
| إعدادات الوكيل والقيم الافتراضية | إدارة | ضبط السلوك العام للوكيل |
| تكوين LiteLLM | إدارة | تمركز إعدادات توجيه النماذج |
| ذاكرة التخزين المؤقت لاكتشاف الأدوات | إدارة | تحديث الأدوات المتاحة |

### متى تستخدم Desk

استخدم `/app` (Desk) عندما تحتاج إلى إنشاء أو تعديل الوكلاء، أو إضافة مزودي/نماذج ذكاء اصطناعي جديدة، أو إنشاء دوال أدوات مخصصة، أو إعداد وكلاء مجدولة أو مدفوعة بالأحداث، أو مراقبة أداء الوكلاء والتكاليف، أو تصحيح المشكلات أو عرض السجلات التفصيلية، أو تكوين الإعدادات على مستوى النظام.

### DocTypes في Desk

تُعدّ DocTypes التالية السجلات الرئيسية التي ستُنشئها وتُديرها داخل مساحة عمل Huf.

| DocType | الغرض |
|---------|---------|
| **Agent** | تعريف الوكلاء بالتعليمات والنماذج والأدوات |
| **AI Provider** | تخزين مفاتيح API لمزودين مثل OpenAI وAnthropic |
| **AI Model** | تحديد النماذج المتاحة |
| **Agent Tool Function** | إنشاء الأدوات التي يمكن للوكلاء استخدامها |
| **Agent Trigger** | تنفيذ الوكيل حسب الجدولة أو الأحداث |
| **Agent Run** | عرض سجلات كل تنفيذ للوكيل |
| **Agent Conversation** | عرض جميع سجلات المحادثات |
| **Agent Chat** | واجهة الدردشة الفورية (موجودة أيضًا في Desk) |
| **Agent Settings** | القيم الافتراضية والإعدادات على مستوى النظام |

## جدول المقارنة

استخدم هذا الجدول لتحديد الواجهة المناسبة لمهمة معينة.

| الميزة | الواجهة الأمامية (`/huf`) | Desk (`/app`) |
|---------|-------------------|---------------|
| **الدردشة مع الوكلاء** | حالة الاستخدام الأساسية | عبر Agent Chat |
| **إنشاء الوكلاء** | غير متاح | تحكم كامل |
| **تكوين الأدوات** | غير متاح | تحكم كامل |
| **عرض محادثاتك** | خاص بالمستخدم | جميع المحادثات |
| **مراقبة تشغيل الوكلاء** | قريبًا | سجلات كاملة |
| **إدارة المزودين** | غير متاح | تحكم كامل |
| **إعداد المشغلات** | غير متاح | تحكم كامل |
| **محسّن للجوال** | قريبًا | يُركز على سطح المكتب |
| **الأذونات المطلوبة** | مستخدم/ضيف | مدير النظام/أدوار مخصصة |
| **تجربة المستخدم** | نظيفة ومركّزة | قوة إدارية كاملة |

## سير العمل النموذجية

توضح هذه السير كيف تتحرك الأدوار المختلفة داخل Huf من أول وصول إلى الاستخدام المستمر.

### للمستخدمين النهائيين

يبدأ المستخدم النهائي في `/huf` على سطح المكتب أو الجوال، ويختار وكيلًا أو يكتشفه، ويتفاعل بشكل طبيعي عبر الدردشة، ويعرض سجل المحادثات، وسيتمكن في النهاية من استدعاء الأدوات الشائعة عبر الاختصارات.

### للمسؤولين

يفتح المسؤول `/app` وينتقل إلى مساحة عمل Huf، ويُنشئ الوكلاء والمزودين والنماذج، ويُعرف الأدوات ويُكوّن المشغلات، ويختبر الوكلاء عبر Agent Chat في Desk، ويراقب التشغيل والتكاليف، ويتكرر بناءً على السجلات.

## خارطة الطريق المستقبلية

تتطور واجهات Huf. تكتسب الواجهة الأمامية ميزات للمستخدمين النهائيين بينما يكتسب Desk ضوابط تشغيلية أعمق.

### توسع الواجهة الأمامية

| الميزة | ما تتيحه |
|---|---|
| **Agent Browser** | اكتشاف الوكلاء وتشغيلهم بسهولة |
| **Tool Shortcuts** | الوصول السريع إلى الإجراءات الشائعة |
| **Conversation Management** | أرشفة الدردشات والبحث فيها وتصديرها |
| **Mobile App** | تجربة جوال أصلية |
| **Public Agents** | مشاركة الوكلاء خارجيًا (بأذونات) |
| **Voice Input** | التحدث مباشرة مع الوكلاء |
| **Rich Media** | الصور والملفات والبيانات المنظمة في الدردشة |

### تحسينات Desk

| التحسين | ما يتيحه |
|---|---|
| تحليلات ولوحات معلومات أفضل | رؤية تشغيلية أعمق |
| أدوات تصحيح متقدمة للوكلاء | حل المشكلات بشكل أسرع |
| توصيات لتحسين التكلفة | تقليل الإنفاق |
| اختبار A/B لتعليمات الوكلاء | مقارنة إصدارات التعليمات |
| التحكم بالإصدارات للوكلاء | تتبع التغييرات والتراجع عنها |

## أفضل الممارسات

تساعد هذه الممارسات في الحفاظ على نظافة الإدارة، وأمان وصول المستخدمين النهائيين، وسلاسة طرح الوكلاء.

### للمؤسسات

احتفظ بالإدارة داخل Desk من خلال جعل المستخدمين الإداريين يُكوّنون كل شيء هناك، ووجّه المستخدمين النهائيين إلى `/huf` للتفاعلات النظيفة والمركّزة، واستخدم **أذونات Frappe القائمة على الأدوار** لفرض الوصول، و**درب المسؤولين** على Desk بينما لا يحتاج المستخدمون النهائيون إلا إلى تعلم `/huf`.

### للمطورين

**ابنِ أدوات مخصصة** في Desk عبر Agent Tool Function، و**اختبر بشكل شامل** في Desk قبل إتاحة الوكلاء في الواجهة الأمامية، و**راقب السجلات** في Agent Run لتصحيح المشكلات، و**تكرر** باستخدام رؤى Agent Run لتحسين التعليمات والأدوات.

## الأمان والأذونات

تحترم كلا الواجهتين نظام أذونات Frappe. يوضح الجدول أدناه كيفية تدفق الأذونات عبر كل واجهة ومكوّن.

| المكوّن | سلوك الأذونات |
|---|---|
| **الواجهة الأمامية** | يرى المستخدمون فقط الوكلاء المسموح لهم بالوصول إليهم |
| **Desk** | أدوار Frappe القياسية (مدير النظام، الأدوار المخصصة) |
| **Agents** | يرث الوكيل أذونات المستخدم الذي يشغله |
| **Tools** | تُنفّذ بأذونات المستخدم الحالي |

<Callout type="warning">
  **مهم**: يعمل الوكلاء دائمًا بأذونات المستخدم الذي أطلقهم. لا يمكن للوكيل الوصول إلى بيانات لا يملك المستخدم إذنًا لرؤيتها.
</Callout>
