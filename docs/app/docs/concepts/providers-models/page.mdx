# Providers & Models

Huf uses **LiteLLM** as a unified routing layer, giving you access to 100+ LLM providers through a single configuration interface. You define providers and models as first-class DocType records, then reference them from agents.

---

## AI Provider DocType

A provider record stores the credentials for one AI service.

| Field | Fieldname | Type | Notes |
|---|---|---|---|
| Provider Name | `provider_name` | Data | Unique name (e.g. `OpenAI`, `Anthropic`, `OpenRouter`). Case-insensitive routing. |
| API Key | `api_key` | Password | Stored encrypted using Frappe's Password field type. Never exposed in plaintext via API. |
| Is Local LLM | `is_local_llm` | Check | When enabled, exposes URL and PORT fields for local model endpoints. |
| URL | `url` | Data | Base URL for local/OpenAI-compatible endpoints (e.g. `http://localhost:11434`). |
| PORT | `port` | Int | Port number for local endpoints. |

> [!IMPORTANT]
> API keys are stored using Frappe's `Password` field type, which applies AES encryption at rest. Keys are only decrypted server-side when making API calls — they are never returned in JSON responses.

---

## AI Model DocType

A model record associates a model name with a provider.

| Field | Fieldname | Type | Notes |
|---|---|---|---|
| Model Name | `model_name` | Data | The model identifier. Can be user-friendly (e.g. `gpt-4-turbo`) or LiteLLM format (e.g. `openai/gpt-4-turbo`). |
| Provider | `provider` | Link → AI Provider | The provider that serves this model. |

## LiteLLM Unified Routing

All LLM calls are routed through [LiteLLM](https://github.com/BerriAI/litellm), which normalises provider-specific APIs into a single OpenAI-compatible interface.

### Model Name Normalisation

You can enter model names in short-form — Huf normalises them automatically using the provider name:

| Short form | Resolved LiteLLM key |
|---|---|
| `gpt-4-turbo` (on OpenAI provider) | `openai/gpt-4-turbo` |
| `claude-3-5-sonnet-20241022` (on Anthropic) | `anthropic/claude-3-5-sonnet-20241022` |
| `gemini/gemini-2.0-flash` | `gemini/gemini-2.0-flash` (passed as-is) |
| `grok-4` (on xAI provider) | `xai/grok-4` |

Provider slug mapping handles common shorthands: `gemini` → `google`, `grok` → `xai`.

If you pass the full LiteLLM format (with a `/` prefix), it is used as-is, bypassing normalisation.

## Supported Providers

| Provider | Notes |
|---|---|
| **OpenAI** | `gpt-4o`, `gpt-4-turbo`, `o1`, `o3-mini`, etc. |
| **Anthropic** | `claude-3-5-sonnet`, `claude-3-haiku`, etc. |
| **Google Gemini** | `gemini-2.0-flash`, `gemini-1.5-pro`, etc. Use provider name `Google`. |
| **OpenRouter** | 500+ models via a single API key. Use `openrouter/` prefix or set provider to `OpenRouter`. |
| **xAI (Grok)** | `grok-4`, `grok-3`, etc. Use provider name `xAI` or `Grok`. |
| **Mistral** | `mistral-large`, `mistral-small`, etc. |
| **Groq** | Fast inference: `llama-3.3-70b-versatile`, `mixtral-8x7b`, etc. |
| **Any LiteLLM provider** | Enter the full LiteLLM model string (e.g. `together_ai/mistralai/Mistral-7B-v0.1`). |

## Local Model Support

Huf supports locally running models through OpenAI-compatible endpoints such as **Ollama** and **LM Studio**.

1. Create an AI Provider with **Is Local LLM** checked.
2. Set the **URL** to your local server (e.g. `http://localhost:11434` for Ollama).
3. Set the **PORT** if different from the URL.
4. Create an AI Model pointing to this provider with the local model name (e.g. `llama3.2`, `phi3`).
5. Assign this model to an agent.

No API key is required for purely local endpoints (you can leave it as a placeholder).

## Prompt Caching

Huf auto-detects prompt caching support using LiteLLM's pricing metadata (`prompt_cache_capabilities.py`). The detection logic checks for a `cache_read_input_token_cost` entry in LiteLLM's model cost database — if that price exists, the model supports caching.

This means caching support automatically picks up **new model releases** without requiring Huf updates.

### Configuring Caching on an Agent

On the **Agent** form, the **Prompt Caching** section exposes:

| Field | Notes |
|---|---|
| Enable Prompt Caching | Master toggle. |
| Cache Control Type | `ephemeral` for Anthropic (charged per write, free on hit); `auto` for OpenAI/Deepseek (fully automatic). |
| Cache System Message | Caches the agent's instructions block. Recommended for agents with long system prompts. |
| Cache Conversation History | Caches multi-turn history messages in long conversations. |

### Provider-Specific Behaviour

| Provider | Cache type | Notes |
|---|---|---|
| Anthropic | `ephemeral` | Cache breaks are explicitly marked; Anthropic charges ~25% extra for cache writes, then 90% discount on hits. |
| OpenAI | `auto` | OpenAI caches automatically for prompts > 1024 tokens. No extra charge for writes. |
| Google Gemini | `auto` | Gemini context caching is available for supported models via LiteLLM. |
| Deepseek | `auto` | Automatic caching at the model level. |

## TTS-Specific Model Configuration

Huf allows you to use a **different provider for Text-to-Speech** than the main inference provider. This is configured on the **Agent** form under **Advanced Settings → Audio Generation**:

| Field | Notes |
|---|---|
| `tts_model` | Link to an AI Model. When set, the TTS API call uses this model's *own provider's* API key. |
| `tts_voice` | Default voice identifier. Examples: `alloy`, `echo`, `nova` (OpenAI); ElevenLabs voice ID (e.g. `21m00Tcm4TlvDq8ikWAM`). |

This enables cross-provider TTS — for example, an agent running on Anthropic Claude with ElevenLabs for voice output.

### Provider-Specific TTS Settings

Huf ships dedicated singleton DocTypes for provider-specific TTS configuration:

- **ElevenLabs Settings** — configure default voice, model ID, and stability parameters.
- **Groq Settings** — Groq TTS/transcription defaults.
- **OpenAI Settings** — OpenAI TTS model and voice defaults.

Access these via **Huf → Settings**.

## Browsing Models

In the Huf interface, the **Models** list view shows all configured AI Models with their linked provider. You can filter, create, and configure models independently of agents, then assign them as needed.
