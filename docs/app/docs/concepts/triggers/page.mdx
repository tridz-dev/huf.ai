# Triggers

**Agent Triggers** define *when* and *how* an agent runs automatically — without a human sending a chat message. Triggers are managed in the **Agent Trigger** DocType, which replaces the old `condition` field that used to live directly on the Agent form.

---

## Agent Trigger DocType Fields

| Field | Fieldname | Type | Notes |
|---|---|---|---|
| Trigger Name | `trigger_name` | Data | Auto-generated unique name |
| Agent | `agent` | Link → Agent | The agent to execute when this trigger fires |
| Trigger Type | `trigger_type` | Select | See types below |
| Disabled | `disabled` | Check | If checked, this trigger will not fire |
| Disabled Reason | `disabled_reason` | Small Text | Why the trigger was disabled (auto-populated in some cases) |
| Is Virtual | `is_virtual` | Check | System-generated trigger (not user-created) |
| Source System | `source_system` | Data | Source app that created this trigger (for virtual triggers) |
| Metadata | `metadata` | JSON | Additional trigger-specific metadata |

---

## Trigger Types

### 1. Doc Event

Fires an agent whenever a specific **document lifecycle event** occurs on a DocType.

**Type-specific fields:**

| Field | Fieldname | Notes |
|---|---|---|
| Reference Doctype | `reference_doctype` | The DocType to listen on (e.g. `Sales Order`) |
| Doc Event | `doc_event` | Event to listen for. See events below. |
| Condition | `condition` | A Python expression evaluated before firing. If it returns `False`, the trigger is skipped. |
| Prompt Field | `prompt_field` | Optional field on the document whose value is used as the primary prompt instruction to the agent |
| File Attachments | `file_attachments` | Child table (`Agent Trigger Attachment`) of fields that hold files to pass to the agent |

**Available doc events:**

```
before_insert, after_insert, before_save, after_save,
before_submit, on_submit, before_cancel, on_cancel,
after_delete, before_update_after_submit, after_update_after_submit,
after_workflow_action
```

**How conditions work:**

```python
# Example: Only fire when the order value exceeds 10,000
doc.grand_total > 10000

# Only fire when status changes to Completed
doc.status == "Completed" and doc.get_doc_before_save().status != "Completed"
```

Conditions use `frappe.utils.safe_exec` and have access to the `doc` object.

**File Attachments (Agent Trigger Attachment):**

Each row in the file attachments child table tells Huf which document fields hold attached files to pass to the agent as context:

| Field | Notes |
|---|---|
| Source Type | `DocField` (a field directly on the document) or `Child Table Field` (a field inside a child table) |
| Child Table | For `Child Table Field` — the fieldname of the child table |
| Attach Field Name | The fieldname that holds the file URL |

When a Doc Event fires, Huf collects all specified file URLs, detects their MIME type, and passes images as inline vision inputs. Non-image files (PDFs, DOCX, etc.) are processed through OCR to extract text, which is appended to the agent prompt as context.

**Execution:**

Doc Event triggers run asynchronously via Frappe's background job queue (`long` queue). The agent receives:
1. A formatted prompt describing the event and document identifiers.
2. The document's JSON data as context.
3. Any extracted file content.

---

### 2. Schedule

Fires an agent on a recurring time schedule.

**Type-specific fields:**

| Field | Fieldname | Notes |
|---|---|---|
| Scheduled Interval | `scheduled_interval` | `Hourly`, `Daily`, `Weekly`, `Monthly`, `Yearly` |
| Interval Count | `interval_count` | Multiplier for the interval (e.g. 2 + Daily = every 2 days) |
| Last Execution | `last_execution` | Datetime of last successful execution (read-only) |
| Next Execution | `next_execution` | Datetime of next scheduled execution (read-only) |

Huf integrates with Frappe's **Scheduler** hooks. On each scheduler tick, Huf checks all active Schedule triggers and fires any that are due.

---

### 3. Webhook

Exposes an agent endpoint that external systems can call via HTTP.

**Type-specific fields:**

| Field | Fieldname | Notes |
|---|---|---|
| Webhook Key | `webhook_key` | Authentication token. Include as `X-Webhook-Key` header or `key` query parameter |
| Webhook Slug | `webhook_slug` | URL slug that identifies this trigger |

**Endpoint URL:**

```
POST /api/method/huf.ai.webhook_handler.handle_webhook?slug={webhook_slug}&key={webhook_key}
```

The webhook handler passes the request body as the agent's prompt payload. External tools, Zapier, Make (Integromat), and other automation platforms can trigger agents this way.

---

### 4. App Event

Fires an agent when a specific named event is emitted by a Frappe app via Huf's event bus.

**Type-specific fields:**

| Field | Fieldname | Notes |
|---|---|---|
| App Name | `app_name` | The Frappe app that emits the event |
| Event Name | `event_name` | The specific event identifier |

Apps fire app events by calling:

```python
from huf.events import fire_app_event

fire_app_event(
    app_name="my_app",
    event_name="customer_onboarded",
    payload={"customer": "Acme Corp", "tier": "Enterprise"}
)
```

---

### 5. Manual

A trigger with no automatic firing mechanism. Used as a configuration template or for triggers that are invoked programmatically.

---

## Conversation History in Triggers

Triggered agents maintain conversation history in the same way as chat agents. The behaviour is controlled by two Agent settings:

| Agent Setting | Default | Effect |
|---|---|---|
| `persist_conversation` | on | Saves conversation history across runs |
| `persist_user_history` | on | Creates separate history per user for Doc Event / Schedule triggers |

**When `persist_user_history` is on:**
- Doc Event runs: history is scoped to the user who modified the document (or the document owner).
- Schedule runs: history is scoped to the trigger owner.

**When `persist_user_history` is off:**
- All runs share a single conversation, keyed as `shared:{agent_name}`.

---

## Concurrency Guard

To prevent duplicate agent runs when the same event fires rapidly (e.g. a doc is saved multiple times in quick succession), Huf uses a Redis-based lock:

```python
lock_key = f"huf:lock:{agent}:{doctype}:{docname}:{event}"
# Expires after 30 seconds
```

If a lock already exists for the same agent + document + event combination, the duplicate trigger is silently dropped.

---

## Cache Invalidation

Doc Event agent assignments are cached in Redis with the key `huf:doc_event_agents`. The cache is invalidated whenever:
- An Agent Trigger is created, updated, or deleted.
- The Agent itself is modified.

This ensures changes to trigger configuration take effect immediately without requiring a server restart.

## Creating a Doc Event Trigger — Example

**Scenario:** Auto-draft a follow-up email when a Sales Order is submitted.

1. Open **Huf → Agent Triggers → New**.
2. Set **Agent** to your email drafting agent.
3. Set **Trigger Type** to `Doc Event`.
4. Set **Reference Doctype** to `Sales Order`.
5. Set **Doc Event** to `on_submit`.
6. Leave **Condition** blank (fires on all submissions), or add:
   ```python
   doc.grand_total > 1000
   ```
7. Set **Prompt Field** to `special_instructions` if your Sales Order has a field for custom agent instructions.
8. Save.

The agent will now run asynchronously in the background every time a Sales Order is submitted (and the condition passes).
