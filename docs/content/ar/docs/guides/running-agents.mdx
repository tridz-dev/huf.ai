# تشغيل الوكلاء

تعرّف على الطرق المختلفة لتنفيذ الوكلاء: الاختبار اليدوي، والتشغيل المجدول، والمشغّلات القائمة على الأحداث، وواجهة الدردشة، واستدعاءات API.

## طرق التنفيذ

يمكن تشغيل الوكلاء بعدة طرق:

1. **التنفيذ اليدوي** - تشغّلها مباشرة
2. **مجدول** - يعمل تلقائيًا وفق جدول زمني
3. **أحداث المستندات** - يُفعّل بتغيّرات المستند
4. **واجهة الدردشة** - تفاعلات المستخدم عبر الدردشة
5. **استدعاءات API** - تنفيذ برمجي
6. **التنسيق متعدد التشغيلات** - مهام معقّدة مقسّمة إلى خطوات متسلسلة

## التنفيذ اليدوي

### متى يُستخدم

**التنفيذ اليدوي هو الأفضل لـ:**
- اختبار الوكلاء
- المهام لمرة واحدة
- تصحيح الأخطاء
- التطوير
- الطلبات العرضية

### الطرق

#### واجهة دردشة الوكيل

**الوصول:** Desk → Huf → Agent Chat

**الخطوات:**
1. اختر الوكيل من القائمة المنسدلة
2. اكتب رسالتك
3. أرسل
4. اعرض الرد

**الأفضل لـ:** الاختبار التفاعلي وتصحيح الأخطاء

#### زر تشغيل الوكيل في DocType

**الوصول:** Desk → Huf → Agent → [اسم الوكيل]

**الخطوات:**
1. افتح الوكيل
2. انقر زر "Run"
3. أدخل التعليمة
4. نفّذ
5. اعرض النتيجة

**الأفضل لـ:** الاختبار السريع من نموذج الوكيل

#### نوع مستند Agent Run

**الوصول:** Desk → Huf → Agent Run → New

**الخطوات:**
1. أنشئ Agent Run جديد
2. اختر الوكيل
3. أدخل التعليمة
4. احفظ (يتم التنفيذ تلقائيًا)
5. اعرض النتائج

**الأفضل لـ:** الاختبار البرمجي وتسجيل السجل

### مسار عمل الاختبار

**العملية الموصى بها:**
1. ابدأ بواجهة Agent Chat للاختبارات السريعة
2. استخدم Agent Run للتسجيل التفصيلي
3. راجِع النتائج في سجلات Agent Run
4. كرّر بناءً على النتائج

## التنفيذ المجدول

### متى يُستخدم

**التشغيلات المجدولة هي الأفضل لـ:**
- التقارير الدورية
- الفحوصات الدورية
- الملخصات اليومية
- المراقبة كل ساعة
- المهام الأسبوعية

### الإعداد

**اضبطها عبر Agent Trigger:**

1. انتقل إلى Desk → Huf → Agent Trigger
2. انقر New
3. اختر الوكيل
4. اختر نوع المشغّل "Schedule"
5. عيّن تكرار الجدولة
6. اضبط قالب التعليمة
7. فعّل واحفظ

### خيارات الجدولة

**التكرارات:**
- **كل ساعة:** كل ساعة
- **يومي:** مرة واحدة يوميًا في وقت محدّد
- **أسبوعي:** أيام محدّدة من الأسبوع
- **Cron مخصّص:** جدولة متقدمة

**أمثلة:**
```
Daily at 9 AM: "0 9 * * *"
Every 6 hours: "0 */6 * * *"
Monday-Friday at 2 PM: "0 14 * * 1-5"
First day of month: "0 0 1 * *"
```

### قوالب التعليمات

**استخدم القوالب لتمرير السياق:**

```
Generate daily sales summary for {date}:
- Total revenue
- Order count
- Top 5 customers
- Trends vs yesterday

Send report to sales@company.com
```

**البيانات الديناميكية:**
- استخدم عناصر نائبة `{field_name}`
- الوصول إلى حقول المستند
- تضمين متغيّرات التاريخ/الوقت
- الرجوع إلى البيانات ذات الصلة

## مشغّلات أحداث المستندات

### متى تُستخدم

**أحداث المستندات هي الأفضل لـ:**
- التحقق عند الإرسال
- التعيين التلقائي عند الإنشاء
- الإشعارات عند التحديثات
- إثراء البيانات عند الإدراج
- أتمتة سير العمل

### الإعداد

**اضبطها عبر Agent Trigger:**

1. انتقل إلى Desk → Huf → Agent Trigger
2. انقر New
3. اختر الوكيل
4. اختر نوع المشغّل "Doc Event"
5. اختر DocType
6. اختر الحدث (After Insert، On Submit، إلخ)
7. أضف الشروط عند الحاجة
8. اضبط قالب التعليمة
9. فعّل واحفظ

### الأحداث المتاحة

| الحدث | متى يُطلق | حالات الاستخدام الشائعة |
|-------|---------------|------------------|
| **After Insert** | عند إنشاء المستند | التعيين التلقائي، الإثراء |
| **On Update** | عند تعديل المستند | الإشعارات، التحقق |
| **On Submit** | عند إرسال المستند | التحقق، سير عمل الموافقة |
| **On Cancel** | عند إلغاء المستند | التنظيف، الإشعارات |
| **Before Save** | قبل الحفظ | التحقق، تصحيح البيانات |

### التنفيذ الشرطي

**أضف عوامل تصفية للحدّ من المشغّلات:**

```json
{
  "status": "Open",
  "priority": "High"
}
```

يُطلق فقط عندما تتحقّق كلا الشرطين.

### قوالب التعليمات

**الوصول إلى حقول المستند:**

```
A new {doctype} has been created: {name}
Customer: {customer}
Total: {grand_total}

Please process this document:
1. Validate the data
2. Assign to appropriate team
3. Send notifications
```

## واجهة الدردشة

### متى تُستخدم

**الدردشة هي الأفضل لـ:**
- التفاعلات الموجّهة للمستخدمين
- دعم العملاء
- المساعدات التفاعلية
- المساعدة الفورية
- سير العمل المحادثي

### الإعداد

**تفعيل الدردشة:**

1. افتح الوكيل في Desk
2. حدّد "Allow Chat"
3. احفظ

**نقاط الوصول:**
- Desk: Agent Chat DocType
- الواجهة الأمامية: واجهة `/huf` (قيد التوسع)

### تجربة المستخدم

**للمستخدمين النهائيين:**
1. الوصول إلى واجهة الدردشة
2. اختر الوكيل أو اكتشفه
3. اكتب الرسالة
4. استلم الرد
5. واصل المحادثة

**الميزات:**
- سجل المحادثة
- إدراك السياق
- التفاعلات متعددة الأدوار
- شفافية استخدام الأدوات

### الصلاحيات

**التحكم في الوصول:**
- يرى المستخدمون فقط الوكلاء التي لديهم صلاحية للوصول إليها
- يحترم صلاحيات Frappe المبنية على الأدوار
- يمكن التقييد حسب المستخدم أو الدور أو القواعد المخصّصة

## التنفيذ عبر API

### متى يُستخدم

**API هي الأفضل لـ:**
- التكاملات الخارجية
- معالجات Webhook
- الواجهات الأمامية المخصّصة
- خدمات الجهات الخارجية
- الوصول البرمجي

### الإعداد

**نقطة النهاية:** `run_agent_sync` (طريقة مدرجة في القائمة البيضاء)

**المصادقة:** مصادقة Frappe API القياسية

**تنسيق الطلب:**
```python
import requests

response = requests.post(
    "https://yoursite.com/api/method/huf.ai.agent_integration.run_agent_sync",
    headers={
        "Authorization": f"token {api_key}:{api_secret}",
        "Content-Type": "application/json"
    },
    json={
        "agent_name": "Customer Support Agent",
        "prompt": "What is the status of order SO-001?",
        "session_id": "api:external_system:12345"
    }
)
```

### المعاملات

**مطلوب:**
- `agent_name`: اسم الوكيل المراد تشغيله
- `prompt`: الرسالة المُرسَلة إلى الوكيل

**اختياري:**
- `session_id`: معرّف جلسة المحادثة
- `context`: بيانات السياق الإضافية
- `stream`: تفعيل الردود المتدفقة

### تنسيق الرد

```json
{
    "response": "Agent's response text",
    "run_id": "RUN-2024-001",
    "tokens_used": 150,
    "cost": 0.0023,
    "tool_calls": [...]
}
```

### إدارة الجلسات

**للمحادثات:**
- استخدم `session_id` ثابتًا
- التنسيق: `{channel}:{user_id}:{identifier}`
- مثال: `api:external_system:user_12345`

**الفوائد:**
- الحفاظ على سياق المحادثة
- تتبّع تفاعلات المستخدم
- تمكين المحادثات متعددة الأدوار

### معالجة الأخطاء

**التعامل مع الأخطاء:**
```python
try:
    response = requests.post(...)
    if response.status_code == 200:
        data = response.json()
        # Process response
    else:
        # Handle error
        error = response.json()
except Exception as e:
    # Handle exception
```

## التنسيق متعدد التشغيلات

### متى يُستخدم

**التنسيق هو الأفضل لـ:**
- المهام المعقّدة التي تتطلب خطوات متعددة
- العمليات طويلة المدى
- المهام التي تحتاج إلى تخطيط قبل التنفيذ
- سير العمل ذو التبعيات المتسلسلة
- مهام البحث والتحليل

### كيف يعمل

عند تفعيل **Multi Run** على وكيل:

1. **المشغّل:** ينشئ استدعاء API مستند تنسيق
2. **التخطيط:** يقسّم الوكيل المهمة إلى خطوات مرقّمة
3. **الجدولة:** تُنفّذ الخطوات واحدة تلو الأخرى (كل دقيقة عبر cron)
4. **السياق:** يحافظ Scratchpad على المعلومات بين الخطوات
5. **الإكمال:** يُعلّم كمكتمل عند انتهاء جميع الخطوات

### الإعداد

**تفعيل Multi-Run:**

1. افتح الوكيل في Desk
2. حدّد **Enable Multi Run**
3. احفظ

بذلك يكون كل شيء! في المرة التالية التي تستدعي فيها هذا الوكيل، سوف:
- ينشئ مستند `Agent Orchestration`
- يولّد خطة
- ينفّذ الخطوات عبر المجدول

### مسار التنفيذ

<Mermaid>{`

`}</Mermaid>

### مراقبة التنسيقات

**عرض التنسيقات:**

انتقل إلى Desk → Huf → Agent Orchestration

**سترى:**
- الحالة (Planned، Running، Completed، Failed)
- رقم الخطوة الحالية
- خطوات الخطة وحالتها
- Scratchpad مع السياق المتراكم
- سجلات الأخطاء إن وجدت

### الاختبار اليدوي

**شغّل المجدول فورًا** (لا تنتظر cron):

```bash
bench --site <site_name> execute huf.ai.orchestration.scheduler.process_orchestrations
```

**التحقق من حالة التنسيق:**

```bash
bench --site <site_name> mariadb -e "SELECT name, status, current_step FROM \`tabAgent Orchestration\` ORDER BY creation DESC LIMIT 5;"
```

**عرض تقدم الخطوات:**

```bash
bench --site <site_name> mariadb -e "SELECT step_index, status, LEFT(output_ref, 80) FROM \`tabAgent Orchestration Plan\` WHERE parent='<orch_name>' ORDER BY step_index;"
```

### مثال على حالة استخدام

**وكيل بحث المحتوى:**

**التعليمة**: "ابحث واكتب منشور مدونة عن الذكاء الاصطناعي في الرعاية الصحية"

**الخطة المُولّدة:**
1. تحديد المواضيع الرئيسية في الذكاء الاصطناعي والرعاية الصحية
2. جمع التطويرات والإحصائيات الحديثة
3. إيجاد دراسات الحالة ذات الصلة
4. إنشاء الخطوط العريضة
5. كتابة المقدمة
6. كتابة الأقسام الرئيسية
7. كتابة الخاتمة
8. المراجعة والتحسين

تُنفّذ كل خطوة باستخدام سياق الخطوات السابقة، مما يبني المخرج النهائي بشكل تدريجي.

### القيود (المرحلة الأولى)

التنفيذ الحالي:
- تُنفّذ الخطوات بشكل متسلسل (بدون توازٍ)
- خطوة واحدة كل دقيقة عبر المجدول
- لا يوجد تدخل يدوي في الخطوات
- معالجة أخطاء أساسية (الفشل يوقف التنسيق)
- لا يوجد آلية إعادة محاولة

### استكشاف الأخطاء وإصلاحها

**التنسيق عالق:**
- تأكّد من أن المجدول يعمل
- شغّل المجدول يدويًا
- راجِع سجل الأخطاء في Agent Orchestration

**فشل الخطوات:**
- تأكّد من أن الوكيل يملك مزود/نموذج صالح
- راجِع مخرجات الخطوات للبحث عن مشاكل في السياق
- راجِع حقل Error Log

**المخرج مُقتطع:**
- `output_ref` هو نص طويل (غير محدود)
- إذا استمرت المشاكل، راجِع scratchpad للحصول على السياق الكامل

## اختيار طريقة التنفيذ

### مصفوفة القرار

| الطريقة | متى تُستخدم | المزايا | العيوب |
|--------|----------|------|------|
| **يدوي** | الاختبار، المهام لمرة واحدة | تحكم كامل، فوري | يتطلب تدخلًا يدويًا |
| **مجدول** | المهام الدورية | أتمتة، موثوقية | توقيت ثابت |
| **حدث المستند** | سير عمل المستندات | تفاعلي، سياقي | مرتبط بأنواع المستندات |
| **دردشة** | تفاعلات المستخدمين | سهل الاستخدام، متاح | يتطلب فعل المستخدم |
| **API** | التكاملات | مرن، برمجي | يتطلب تطويرًا |
| **تنسيق** | المهام المعقّدة متعددة الخطوات | يتعامل مع التعقيد، يحافظ على السياق | غير متزامن، تنفيذ أبطأ |

### الجمع بين الطرق

**يمكنك استخدام طرق متعددة:**
- الدردشة للتفاعلات المستخدمة
- الجدولة للتقارير
- أحداث المستندات للأتمتة
- API للتكاملات

**مثال:**
- وكيل دعم العملاء: دردشة + API
- مولّد التقارير: مجدول
- مدقّق الفواتير: حدث المستند
- مؤهّل العملاء المحتملين: حدث المستند + API

## اعتبارات الأداء

### أوقات الاستجابة

**العوامل المؤثرة على السرعة:**
- اختيار النموذج (النماذج الأسرع = ردود أسرع)
- تعقيد الأدوات (مزيد من الأدوات = مزيد من الوقت)
- سجل المحادثة (أطول = أبطأ)
- زمن استجابة الشبكة (لاستدعاءات API)

### التحسين

**تحسين الأداء:**
- استخدم نماذج أسرع عندما يكون ذلك ممكنًا
- قلّل استدعاءات الأدوات
- حدّد سجل المحادثة
- خزّن النتائج الشائعة
- حسّن استعلامات الأدوات

### إدارة التكلفة

**مراقبة التكاليف:**
- تتبّع استخدام الرموز
- راجِع سجلات Agent Run
- حسّن التعليمات
- استخدم نماذج أرخص عندما يكون ذلك مناسبًا
- حدّد سجل المحادثة

## استكشاف الأخطاء وإصلاحها

**الوكيل لا يعمل:**
- تأكّد من أن الوكيل Active
- تأكّد من أن المشغّل Enabled
- راجِع الصلاحيات
- راجِع سجلات الأخطاء
- اختبر يدويًا أولًا

**التشغيلات المجدولة لا تعمل:**
- راجِع إعدادات الجدولة
- راجِع تعبير cron
- تأكّد من أن الوكيل Active
- راجِع سجلات المجدول
- اختبر باستخدام المشغّل اليدوي

**أحداث المستندات لا تُطلق:**
- تأكّد من اختيار DocType
- راجِع نوع الحدث
- راجِع الشروط
- اختبر بالتنفيذ اليدوي
- راجِع الصلاحيات

**استدعاءات API تفشل:**
- تأكّد من المصادقة
- راجِع عنوان URL لنقطة النهاية
- راجِع تنسيق الطلب
- راجِع اسم الوكيل
- راجِع رسائل الخطأ
