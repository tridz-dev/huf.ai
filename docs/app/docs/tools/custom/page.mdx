# Custom Tools

Beyond the built-in Frappe data tools and integration tools, HUF lets you define your own tools using Python functions, HTTP endpoints, or tools registered by other Frappe apps.

---

## Custom Function

The **Custom Function** type lets you point an `Agent Tool Function` at any Python function in your Frappe apps or custom scripts.

**Type value:** `Custom Function`  
**Function Path:** Dotted Python path to the function (e.g., `my_app.api.my_function`)

### How it works

1. HUF dynamically imports the module and gets the function via `getattr`
2. The agent's runtime arguments (parsed from JSON) are passed as `**kwargs`
3. If the function accepts `**kwargs`, all arguments are passed through
4. If the function has a fixed signature, only matching parameter names are passed
5. The return value is JSON-serialized and sent back to the agent

### Function Signature

Your function can accept any combination of named parameters. HUF injects a few special context values automatically:

- `conversation_id` — the current conversation ID (if running in a chat context)
- `agent_run_id` — the current `Agent Run` document name
- `agent_name` — the name of the calling agent

```python
# my_app/api.py

def get_customer_summary(customer_name: str, conversation_id: str = None, **kwargs) -> dict:
    """Return a summary dict for a customer."""
    customer = frappe.get_doc("Customer", customer_name)
    orders = frappe.get_list("Sales Order", filters={"customer": customer_name}, fields=["name", "grand_total"])
    return {
        "customer": customer.customer_name,
        "total_orders": len(orders),
        "outstanding": customer.outstanding_amount
    }
```

### Configuration

| Field | Value |
|---|---|
| **Types** | `Custom Function` |
| **Function Path** | `my_app.api.get_customer_summary` |
| **Pass Parameters as JSON** | If checked, parameters are passed as a single JSON string rather than individual kwargs |

### Pass Parameters as JSON

When **Pass Parameters as JSON** is enabled, the agent's arguments are serialized to a JSON string and passed as a single argument. Useful when your function expects to parse its own JSON payload.

## App Provided

The **App Provided** type is for tools that another Frappe app **registers** by implementing the HUF tool provider interface. The tool handler is still a Python function, but the `provider_app` field identifies which app owns it.

**Type value:** `App Provided`

### How it works

App Provided tools work identically to Custom Function tools at runtime — the `function_path` points to a handler function. The `provider_app` field is metadata that identifies the Frappe app that owns the tool, enabling the App Seeding system to track tool provenance.

### App Seeding Integration

Apps that want to register their tools with HUF can define an `huf_tools` hook in their `hooks.py` (see App Seeding documentation). The seeder creates `Agent Tool Function` documents with `types = "App Provided"` and `provider_app` set to the app name.

```python
# hooks.py in your Frappe app
huf_tools = [
    {
        "tool_name": "search_knowledge_base",
        "description": "Search the internal knowledge base for answers.",
        "function_path": "my_app.tools.search_kb",
        "category": "Custom Tools",
        "parameters": [
            {"fieldname": "query", "type": "string", "required": 1, "description": "Search query"}
        ]
    }
]
```

## GET and POST HTTP Tools

HUF supports calling external HTTP APIs as agent tools, with optional base URL configuration and custom request headers.

### GET Tool

**Type value:** `GET`  
**Function Path:** `huf.ai.http_handler.handle_get_request`

Makes an HTTP GET request to a URL determined by the agent.

### POST Tool

**Type value:** `POST`  
**Function Path:** `huf.ai.http_handler.handle_post_request`

Makes an HTTP POST request with a JSON body determined by the agent.

### Configuration Fields

| Field | Fieldname | Description |
|---|---|---|
| **Base URL** | `base_url` | Optional prefix prepended to the URL the agent provides. Use this to lock the tool to a specific domain. |
| **HTTP Headers** | `http_headers` | Child table of `Agent Tool HTTP Header` rows for custom request headers |

### Agent Tool HTTP Header Child Table

Add static HTTP headers to every request made by this tool:

| Field | Description |
|---|---|
| **Header Name** | HTTP header name (e.g., `Authorization`, `X-API-Key`) |
| **Header Value** | Header value |

### Example: Internal API call tool

```
Tool Name: get_product_stock
Type: GET
Base URL: https://inventory.mycompany.com/api
HTTP Headers:
  Authorization: Bearer <internal-token>
  Accept: application/json

Parameters:
  url (string, required) - The API path to call (e.g., /products/SKU-001/stock)
```

The agent would call `get_product_stock` with `url="/products/SKU-001/stock"`, and HUF prepends the base URL to form `https://inventory.mycompany.com/api/products/SKU-001/stock`.

## Defining Parameters

### Agent Function Params Child Table

Every parameter the agent can pass is defined as a row in the **Parameters** child table of the `Agent Tool Function`.

| Column | Description |
|---|---|
| **Label** | Human-readable label (auto-derived from fieldname, e.g., `customer_name` → `Customer Name`) |
| **Fieldname** | Parameter key — this is what the LLM uses in its function call |
| **Type** | JSON schema type: `string`, `integer`, `number`, `boolean`, `array`, `object` |
| **Required** | Check if the LLM must always provide this parameter |
| **Description** | **Write this carefully.** The LLM reads this description to know what value to pass. |

### Function Definition JSON (Auto-generated)

After saving, the **Function Definition** field is automatically populated. This is the JSON schema sent to the LLM:

```json
{
  "name": "get_customer_summary",
  "description": "Return a revenue and order summary for a customer.",
  "parameters": {
    "type": "object",
    "properties": {
      "customer_name": {
        "type": "string",
        "description": "The Frappe Customer document name"
      }
    },
    "required": ["customer_name"]
  }
}
```

You can also provide the full schema directly in the **Params JSON** field if you need advanced schema features (e.g., `enum`, `anyOf`, `minLength`) that the child table UI doesn't support.

## Agent Tool Type

Every `Agent Tool Function` must be linked to an `Agent Tool Type` document via the **Tool Type** field. This is a categorization/tagging layer.

Default tool types seeded by HUF include categories like `Communication Tools`, `Google Tools`, `Developer Tools`, `Frappe Data Tools`, etc.

To create a custom category:

1. Go to **HUF → Agent Tool Type → New**
2. Set a **Tool Type Name** (e.g., `Internal Integrations`)
3. Optionally add a description
4. Save, then reference it in your `Agent Tool Function`

## Security Considerations

### SSRF Protection

When using GET/POST HTTP tools, the base URL configuration is your primary SSRF guard. By setting a `base_url`, you constrain the agent to a specific host. Without a `base_url`, the agent can supply any URL — consider this only for trusted, internal agents.

### Guest User Blocking

Mutating custom tools (Create, Update, Delete, POST) are blocked for `Guest` users by the `MUTATING_TOOL_TYPES` guard in `PermissionAwareToolRegistry`. Read-only custom functions can be made available to Guest users by:

1. Checking **Allowed for Guest** on the `Agent Tool Function`
2. Ensuring the function handles unauthenticated execution safely (validate input, don't expose sensitive data)

When a Guest-allowed tool runs, `ignore_permissions=True` is injected automatically into the kwargs.

### Custom Function Security

- Custom functions run in the Frappe process with the session user's permissions
- Never trust `kwargs` input without validation — the LLM can be prompted to supply unexpected values
- Use `frappe.has_permission()` inside your function for sensitive operations
- Avoid exposing functions that take arbitrary Python code or system commands as parameters

```python
# ✅ Safe — validates and restricts what can be queried
def get_approved_report(report_key: str, **kwargs) -> dict:
    allowed_reports = ["monthly_sales", "customer_aging", "stock_ledger"]
    if report_key not in allowed_reports:
        return {"error": "Report not permitted"}
    return run_report(report_key)

# ❌ Unsafe — agent can supply any DocType/SQL
def run_arbitrary_query(sql: str, **kwargs) -> dict:
    return frappe.db.sql(sql, as_dict=True)  # Never do this
```
